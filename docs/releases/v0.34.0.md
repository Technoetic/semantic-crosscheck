# semantic-crosscheck v0.34.0 — PostgreSQL 17 catalog precision, zero-extra-round-trip relation disclosures and paired fixture leakage audit

Release date: 2026-11-24.

## What it is

This minor release tightens PostgreSQL 17 catalog inspection precision in `doctor` and `grain` with zero extra SQL round trips and adds an opt-in, Python standard-library structural fixture deduplication and split-leakage audit to `tools/paired_release.py`. Runtime Python requirements (`requirements/*.txt`), default operational pipeline stages, default `doctor` output on ordinary populated tables, existing `examples/paired-release/` receipts, and the Cube `1.8.3` adapter lockfile are unchanged.

## Highlights

- **PostgreSQL 17 `pg_index` precision fix (`doctor.py`, `grain.py`, `tests/test_rls_catalog_pg.py`):**
  - Tightens `unique_nulls_not_distinct` detection in both `doctor._privileges_sql()` and `grain.evaluate()` to require `i.indisunique AND i.indisvalid AND i.indisready AND i.indpred IS NULL AND i.indexprs IS NULL AND i.indnullsnotdistinct`, eliminating false positives on invalid, partial (`WHERE ...`), and expression (`lower(...)`) unique indexes while preserving exact detection of plain full `UNIQUE NULLS NOT DISTINCT` indexes.
- **Zero-extra-round-trip PostgreSQL 17 relation-hygiene guards (`doctor.py`, `grain.py`, `docs/grain.md`, `tests/test_rls_catalog_pg.py`):**
  - Extends `doctor._privileges_sql()` in place (zero extra SQL round trips) with `relkind`, `relispopulated`, `relhasrules`, unvalidated `CHECK`/`FOREIGN KEY` constraint counts (`pg_constraint.convalidated = false`), and recursive `pg_inherits` child-partition RLS detection (`child_partition_row_security`).
  - Fails closed on unpopulated materialized views (`relkind = 'm'`, `is_populated = false`) on `privileges:select:<entity>` with a direct `REFRESH MATERIALIZED VIEW` hint, preventing downstream `SELECT` crashes while keeping populated materialized views passing.
  - Emits explicit `not_proven` disclosures in `doctor` for unvalidated `NOT VALID` constraints, foreign tables (`relkind = 'f'`, outside `REPEATABLE READ` snapshot isolation), ordinary/partitioned table rewrite rules (`relhasrules = true`, never false-firing on views or materialized views), and child-partition RLS asymmetry (`child_partition_row_security = true` while parent `relrowsecurity = false`).
  - Extends `grain.evaluate()` within its existing five-statement budget (`statement_budget = 5`) to record `source_child_partition_row_security` / `node_child_partition_row_security` and disclose child-partition RLS asymmetry in `not_proven` without leaking relation identifiers.
- **Opt-in paired fixture structural leakage audit (`tools/paired_release.py`, `docs/paired-release.md`, `tests/test_paired_release.py`):**
  - Adds `--fixtures-dir <DIR>` and `--check-fixture-leakage` in the Python standard library (zero new dependencies, 100% default backward compatibility).
  - Fails closed with exit `2` on symlinked or reparse-point fixture directories/files, unsafe `case_id` path traversal, missing files, files exceeding 1 MiB, `fixture_sha256` mismatches against `plan.json`, duplicate JSON keys, nonfinite constants, or non-object payloads.
  - Computes both `canonical_json_sha256` (whitespace- and key-order-invariant) and `alpha_structural_sha256` (row-order-independent and domain-string α-renamed while preserving dict keys, top-level mode strings, exact numeric/boolean/null types, and cross-row identifier equality), emits `fixture_leakage_audit` with zero row contents or local paths, and fails closed with exit `1` under `--check-fixture-leakage` on cross-split (`development`↔`heldout`) or within-split collisions (0 collisions on `examples/paired-release/cases`).

## Known limitations

- `doctor` and `grain` inspect PostgreSQL catalog state at check time; DDL changes (such as `REFRESH MATERIALIZED VIEW`, `ALTER TABLE ... VALIDATE CONSTRAINT`, or child-partition RLS changes) after `doctor` or `grain` runs are not retroactively detected until stages are rerun.
- `child_partition_row_security` discloses asymmetric RLS on child partitions or inherited tables when the parent has `relrowsecurity = false`; it does not inspect policy predicate semantics or guarantee equivalence between parent and child queries.
- `tools/paired_release.py --check-fixture-leakage` detects cosmetic reformatting and domain-string α-renaming / row-reordering duplicates across JSON fixtures using color refinement plus bounded individualization (up to 16 tied orbits, canonical tie-selection up to 32 strings per orbit); highly regular fixtures exceeding those bounds can yield false negatives, and the check does not detect numeric rescaling, semantic query-only paraphrases, or whether `heldout` labels were viewed by an author.
- Package code and `semantic_crosscheck/__init__.py` version increment to `0.34.0`, which updates `engine_sha256` in stage provenance; rerun operational stages after upgrading.
