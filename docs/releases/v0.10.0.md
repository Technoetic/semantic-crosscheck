# semantic-crosscheck v0.10.0

Release date: 2026-10-25. A minor release adding a generated-shape preflight and an optional NoREC
count oracle, and correcting incomplete sampled and chunked pair-response accounting.

## What it is

semantic-crosscheck generates PostgreSQL hierarchy closures, SQL and SHACL rules, OWL/HermiT reasoning
and a Cube semantic layer from one configuration, then compares their results and hand-written gold SQL.
This release makes incomplete responses explicit and adds independent, bounded validation checks.

## Highlights

- **Complete pair-response accounting.** Sampled V3 and V4 replay require each requested key in the
  together and every alone response; chunked non-NULL keys receive the same guard. Confirmed mismatches
  or duplicates still fail. Otherwise missing answers are `not_run` (`keys_not_answered`), not NULL-valued
  measures or evidence that a mutation was killed. Only fully answered keys count. An incomplete sample
  claims neither completed comparison nor a D95 bound; complete samples retain the existing assumptions.
- **Generated-shape preflight.** `reason` runs `shacl:meta:generated` once before source export with pinned
  pySHACL's shacl-shacl syntax subset. Nonconformance fails; parsing, engine or malformed-report problems
  are sanitized errors. Affected SHACL comparisons remain `not_run` (`generated_shapes_invalid`), while
  independent OWL may proceed. Invalid reports and shape values are not logged.
- **Optional NoREC count oracle.** `tlp --oracle norec --spec examples/tlp/norec-count.json` independently
  compares WHERE-count with CASE/SUM-count for exactly `count(*)`. It bounds the materialized relation,
  validates integer counts and observable row/predicate stability, and binds replay to its oracle. The
  default remains TLP and existing TLP replay stays compatible. NoREC retains the standalone `tlp` stage
  and output directory; result inputs, check IDs and replay format identify the selected oracle.

## Compatibility and migration

Existing configuration and dependency pins remain supported; no new package or configuration field is required.
Default behavior becomes more conservative: incomplete sampled answers, including legitimate sparse standalone
results without independent existence evidence, can now remain `not_run`. The unfiltered path at or below the
2,000-key cap and existing NULL-group semantics are unchanged. The generated-shape preflight is automatic in
`reason`; NoREC is opt-in and supports no aggregate other than `count(*)`.

Rerun `build`, `reason`, `cube`, `verify` and `report` after upgrading because the engine fingerprint changes.
Installing the release neither reruns stages nor certifies old evidence.

## Known limitations

- Absent sparse standalone answers may legitimately mean no facts; without independent existence evidence,
  sampled/chunked comparisons conservatively remain unverified. The guard does not establish data completeness.
- Samples omit the NULL key group and may miss disagreements outside the sample. Complete-sample D95 retains
  its documented assumptions. Each Cube query has its own snapshot, shared with neither other Cube queries nor SQL.
- Meta-SHACL checks only the provided shacl-shacl syntax subset, not full SHACL validity or business semantics.
  The fixed exporter corpus and external W3C engine corpus remain separate checks.
- NoREC materializes a bounded relation and therefore limits optimizer/index coverage. Predicate-count agreement
  is not full result equivalence or proof of business correctness. Synthetic results do not promote operational V1-V5.
- No shared cross-stage MVCC snapshot or runtime attestation is claimed. Existing [v0.9.0 limitations](v0.9.0.md#known-limitations)
  still apply except its sampled-answer-coverage gap, which this release addresses for the documented paths.
