# semantic-crosscheck v0.7.0

Release date: 2026-10-21. A minor release adding structured reduction and typed finite-domain
synthetic inputs to the optional two-query counterexample search. The configuration format remains
version 1; PostgreSQL still decides whether the two supplied queries disagree on each tested input.

## What it is

semantic-crosscheck generates a PostgreSQL hierarchy closure, SQL and SHACL data rules, OWL/HermiT
reasoning and a Cube semantic layer from one configuration, then compares the results with each other
and with hand-written gold SQL. Its separate synthetic counterexample command looks for concrete
disagreements between two trusted SQL files without using operational data.

## Highlights

- **Structured reduction, explicitly selected.** `--shrink-strategy structured` starts with single-row
  deletion, then tries reverse foreign-key dependency groups and finite-rank simplification of non-key
  values. Every accepted step preserves the declared integrity domain and an actual PostgreSQL
  disagreement. All transformations share `--max-shrink-steps`; after an accepted step, row deletion
  restarts. The reported minimality covers admissible single-row deletion only, not a globally smallest
  input or every possible value change.
- **Typed finite domains.** `--witness-schema FILE` replaces a built-in scenario with declared tables,
  row bounds, column types and finite value lists. Optional Z3 models row counts and cell choices,
  respecting supported PK, UNIQUE, NOT NULL, MATCH SIMPLE FK and allowlisted CHECK constraints.
  A total `--solver-timeout-ms` budget covers compilation and enumeration (default 3,000 ms).
  SQL query conditions are not encoded in Z3: both queries are executed and compared in PostgreSQL.
- **Input-bound replay.** Extended fixtures use version 2, binding the exact declaration, profile and
  SQL bytes, original synthetic input, generator, reduction strategy and accepted transformation trace.
  Replay checks the supported transformations and declared domain at each step, then compares the final
  SQL results. Public result summaries contain counts and identifiers; fixture files contain synthetic
  rows. The default row-only path and legacy version 1 replay remain supported.
- **Exact numeric boundary validation.** Valid 29–38-digit numeric boundaries are checked without
  rounding caused by a caller's ambient Decimal precision.

## Compatibility and migration

Existing version 1 configurations and commands need no new option. The default shrink strategy remains
`rows`. The new generation and reduction options apply only to two-query comparison, not metamorphic or
mutation modes. A witness declaration and `--scenario` are mutually exclusive; a non-default solver
budget requires schema mode. See the [counterexample reference](../../skills/semantic-crosscheck/references/counterexamples.md#structured-reduction-and-typed-finite-domain-inputs)
for the full declaration, bounds and trusted-SQL contract.

Core and reasoning dependencies, the Cube 1.8.3 pin and its lockfile are unchanged. Typed generation adds
an optional MIT-licensed `z3-solver==4.15.3.0` requirement; it is imported only when schema mode needs it.
Install it from the actual plugin root when using `--witness-schema`:

```text
python -m pip install -r "<plugin root>/requirements/witness.txt"
```

Rerun the complete pipeline after upgrading (`build`, `reason`, `cube`, `verify`, then `report`): the
engine fingerprint changes and earlier results become stale. Preserved legacy fixture replay is a
separate compatibility contract; prior stage PASS results do not become current automatically.

## Known limitations

Typed generation supports text, 32-bit integer, ISO date and `numeric(p,s)` with precision 1–38 and
scale 0–precision. Bounds are four tables, eight columns per table, four rows per table, eight distinct
values per column and 64 cells total; the declaration is limited to 256 KiB. This is a user-declared
finite domain, not inferred database schema or query-directed SQL solving. Missing solver, bounded
UNSAT, unknown, timeout or no disagreement is `not_run`/`not_proven`, never an equivalence proof.

Reduction preserves protected key columns, declared row bounds and finite value domains. The budget
can stop before a local minimum. Replay validates the recorded reductions and final disagreement;
it does not prove universal query equivalence or global minimality. SQL files must be trusted: CTE
wrapping and read-only transactions are not a sandbox for hostile SQL.

No operational-data correctness, shared MVCC snapshot across Cube or stages, OWL classification proof
from these synthetic inputs, or runtime attestation is claimed. Existing scope and resource limits
from the [v0.6.0 notes](v0.6.0.md#known-limitations) still apply.
