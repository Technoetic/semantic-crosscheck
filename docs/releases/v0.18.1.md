# semantic-crosscheck v0.18.1

Release date: 2026-11-04. This is the first formal bundle of the boundary
fixes prepared in the v0.18.0 source, plus a CI infrastructure recovery patch.
No formal v0.18.0 release was published; its existing tag is preserved.
The only new patch behavior selects macOS 15 Intel unit runners after hosted
arm64 capacity failures. Product behavior, dependency/runtime pins, default
pipeline stages and report authority are unchanged from that source.

## What it is

semantic-crosscheck generates PostgreSQL hierarchy closures, SQL/SHACL rules,
OWL/HermiT reasoning and a Cube semantic layer, then cross-checks them against
each other and independently authored gold SQL. These fixes preserve exact input
values, reject ambiguous result schemas and apply shared response acceptance
bounds in normal and replay Cube paths.

## Highlights

- **CI recovery only in this patch.** Replace `macos-latest` with the standard
  `macos-15-intel` label (macOS 15 x64). The v0.18.0 main/tag runs each completed
  their six non-Mac jobs successfully, including strict integration, while
  all four Mac jobs across both runs were cancelled with no runner and zero
  steps. GitHub reported runner acquisition failure and arm64 capacity
  constraints. Linux/Windows latest and Python 3.11/3.13 retain six unit jobs;
  strict integration and hygiene retain eight jobs in total. Steps, action
  pins, no-skip guards and real-engine checks are unchanged. A focused
  regression protects that contract. Intel success remains unobserved until
  the new-source CI executes; Mac arm64 coverage is not claimed.

The bundled functional fixes below are unchanged from the v0.18.0 source:

- **Validate raw Cube JSON before information is lost.** Duplicate object keys
  at every depth and nonfinite constants are rejected. Duplicate rejection is
  the checker's strict policy, not a claim that every JSON syntax specification
  forbids duplicate names. Fractional JSON numbers use exact `Decimal` values;
  integers, strings (including numeric strings), booleans and null retain their
  existing meaning. Invalid raw load JSON, encoding and Decimal parse failures
  become sanitized `CubeResponseError` results without returned values.
  An additional aggregate raw-number expansion budget rejects oversized
  fixed-point lengths before formatting. It covers nested raw Decimal values,
  counts zero as one character and preserves admitted values exactly.
- **Validate Gold SQL metadata before constructing dictionaries.** Column
  labels must be nonblank strings and unique. Every `gold.map` column must be
  present even when the result has zero rows, and every row must match the
  returned width. Distinct extra unmapped SQL columns and valid empty results
  remain allowed. Invalid metadata produces a sanitized Gold error while the
  existing read-only transaction and prepared-statement cleanup remain intact.
- **Bound Cube response acceptance.** Normal and replay loads share one
  monotonic elapsed query budget across polling, reads, decoding and final
  acceptance. Successful and HTTP-error source bodies have a default **16 MiB**
  cap, independent of a claimed `Content-Length`. This cap is on source-body
  bytes, not total heap. See [Cube HTTP bounds](../cube-http.md) for the exact
  defaults, constructor override and transport limitations.

## Compatibility and migration

The CI architecture changes from the `macos-latest` arm64 pool to macOS 15
Intel. This changes the platform tested, not the supported Cube native-module
list. The previous tag's partial CI is historical evidence only; new-source
main and annotated-tag runs must establish their own results. See the
[CI recovery ruling](../plans/2026-11-04-boundary-hardening.md#ci-infrastructure-recovery-ruling--v0181).

The bundled boundary fixes have these migration implications:

Previously accepted duplicate-key, rounded or malformed responses may now be
rejected or expose a real mismatch. Invalid bodies and schema errors cannot
establish equality, a confirmed witness or a mutation kill. Repair the adapter
answer or SQL metadata; do not turn an operational error into comparison data.
The load error normalization does not change the existing native JSON/Decimal
decode-exception behavior of the metadata endpoint. Successfully decoded metadata
that exceeds the numeric expansion allowance raises `CubeResponseError`, as
with the response-body cap.

`CubeClient` keeps its 120-second default timeout and adds
`max_response_bytes=16 * 1024 * 1024`. The timeout must be a finite positive
nonboolean number; the cap must be a positive nonboolean integer. The same integer
sets a separate per-response numeric expansion character allowance, counting
signs, decimal points and fractional trailing zeros before stripping them. An
override can accommodate a larger trusted source body or raw-number expansion,
but cannot make transport calls hard cancellable or establish semantic coverage.
The existing row limit applies
independently. Health readiness remains a separate boolean probe.

Rerun operational stages after upgrading: the engine fingerprint changes with
the package. Installing this release neither executes stages nor refreshes
evidence. No new dependency, runtime pin, default stage or report authority is
introduced, and these changes do not certify any company database.

## Known limitations

- Standard supported Intel runners can also encounter capacity limits.
  The workflow configures Mac unit checks only; provisioned full-stack
  PostgreSQL/HermiT/Cube/Jena integration remains Linux x64. No arm64 Mac
  execution or Intel pass is inferred from the label change.
- The HTTP deadline is an **elapsed acceptance budget**, not hard wall-clock
  cancellation. DNS, connect/redirect handling, response headers and HTTP chunk
  framing can delay control returning; a late result is rejected once it returns.
  No background transport worker or private socket manipulation is introduced.
- The 16 MiB limit bounds source-body bytes yielded to the accumulator, not
  kernel buffering, HTTP metadata, parsed JSON object memory or parsing CPU time.
  Its separate raw-number character allowance is conservative, not a total-heap
  or CPU guarantee or a global policy for numeric strings. Canonical, RDF and
  hash representations remain unchanged.
- Strict decoding and metadata validation cannot detect a shared business-rule
  error in the configuration, independently authored expectations and model.
- Cube and SQL reads still do not share a guaranteed cross-session MVCC snapshot.
  Current-data witnesses do not prove future-data or general SQL equivalence.
- Local optional-engine skips do not establish unexecuted engine or platform
  behavior. Public CI must record its own results on the exact release source.
- Existing [v0.17.0 limitations](v0.17.0.md#known-limitations) continue to apply.
