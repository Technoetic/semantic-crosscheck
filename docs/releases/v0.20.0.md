# semantic-crosscheck v0.20.0

Release date: 2026-11-06.

## What it is

semantic-crosscheck cross-checks PostgreSQL, SHACL, OWL/HermiT and Cube against
independently authored Gold SQL. This release adds an optional offline boundary
before execution: explicitly declare what a business metric means and check a
structured plan against that declaration.

## Highlights

- **Business-definition contracts.** Stable metric IDs, declared labels/aliases,
  definitions and caller review assertions bind to existing measure, Gold and
  generated Cube-member declarations. Unit, grain, population, aggregation,
  denominator and time context are explicit; synonyms are never inferred.
- **Structured-plan preflight.** `semantic-preflight --config FILE --contract
  FILE --plan FILE` checks the chosen metric, binding, context and typed period.
  Missing, ambiguous or candidate selections return existing `not_run` with
  `needs_clarification`; complete conflicts fail. No SQL is generated/executed.
- **Bounded, redacted inputs.** Capture each input within 256 KiB, parse strict
  JSON and TOML bytes without rereading config, protect observed path aliases
  and changed inputs, and publish only hashes/indexes/fixed reasons. No Gold or
  revision SQL body, company database, external model or network is read.
- **Executable synthetic example.** One self-contained part/stock example and
  `/xc-preflight` command document both the useful checks and their limits.

See [schema and examples](../semantic-preflight.md). The two NVIDIA sources
already referenced by agentic-vault are reused for this different application;
no NVIDIA source code or runtime is incorporated.

## Compatibility and migration

The command is explicit and optional. Existing pipeline stages, report authority,
Result statuses and dependency pins remain unchanged. Operational report binding
for contract/plan sidecars is deferred. Rerun operational stages after upgrading:
new Python engine files change the existing generic engine fingerprint, even
though this diagnostic does not become a required report stage.

## Verification evidence

| Evidence | Scope |
|---|---|
| Unit tests | Fresh complete local and six OS/Python matrix totals are recorded from actual output in verification.json |
| Integration tests | Fresh provisioned PostgreSQL17, HermiT, Cube and Jena suite must have zero skips/failures/errors and a nonzero count |
| CI run | Exact final main and annotated tag each require all eight mandatory jobs |
| Leak scan | Worktree and complete-history generic scan; unavailable private denylist coverage is not claimed |
| Independent verification | Separate evaluator/IO review, exact Git-blob archive comparison and fresh draft/public downloads |
| Native plugin | Isolated Codex discovery and packaged version/help/offline example; no global plugin installation changes |

Actual source SHA, job URLs, per-job counts, local skips and asset digests belong
in the release's `verification.json` after execution. Optional local/unit skips
are distinct from the strict zero-skip integration gate. macOS CI is Intel x64;
no ARM64 execution is claimed.

## Checksums

Assets: committed-source ZIP, `verification.json` and UTF-8/LF `SHA256SUMS`.
Each ZIP member is checked against its Git blob. Cross-toolchain/timezone ZIP
byte reproducibility is not claimed. Independent draft and postpublication
anonymous downloads plus immutable release/asset attestations are separate gates.

## Known limitations

- `reviewed` is an unauthenticated caller assertion, not authenticated approval.
- Matching authored definitions may share the same mistake. Population, unit,
  denominator, timezone and time semantics are not independently inferred or
  verified against SQL. Definition prose is not parsed for meaning.
- Plan periods are calendar declarations, not Gold parameter bindings or proof
  of SQL/Cube filtering, data availability, correctness or query equivalence.
- Only existing generated measure-value members and selected Gold declarations
  are mapped offline; arbitrary live Cube metadata is not discovered.
- Input guards provide observed local change/path checks, not a filesystem lock
  or a defense against hostile concurrent ancestor replacement.
- Diagnostic results do not authorize production execution or become operational
  report evidence. Core contract/plan freshness integration remains deferred.
- Existing operational snapshot, OWL/SHACL/SQL scope and synthetic-check limits
  remain. No private denylist or company database verification is claimed.
