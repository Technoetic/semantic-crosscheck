# semantic-crosscheck v0.1.1

Released 2026-10-14. A patch release for three verification defects.

## What it is

semantic-crosscheck checks agreement between PostgreSQL 17, generated SHACL and OWL rules, HermiT,
the Cube semantic layer and hand-written gold SQL. This release strengthens the verdicts and configuration
validation of v0.1.0; the configuration format remains version 1.

## Highlights

- **Resource limits leave explicit failures to run.** If SHACL exceeds its row limit or OWL exceeds its
  individual limit, the selected checks remain `not_run` with `reason=resource_limit`. Neither `reason`
  nor `report` can pass just because the other engine completed. The next action asks for a limit review
  and a fresh reasoning run.
- **Exact decimal comparison.** Canonicalisation preserves every decimal digit independently of the
  active Decimal context. Values and numeric keys differing after the 28th digit remain distinct.
- **Unknown configuration options fail early.** Extra keys in entities, ontology entries, defined
  classes and gold parameter specifications raise a configuration error instead of dropping a rule.
  User-defined names in mapping tables and Cube API query payloads remain supported.
- **Integration CI requires every test to run.** The PostgreSQL 17 / Java 21 / Node.js 22 job fetches
  full Git history and fails on any skipped test, an empty suite or an unsuccessful result. Core-only
  unit jobs still skip tests whose optional services are absent.
- Twelve regression cases cover the three defects. Document checks now cover all release notes.

## Install

Claude Code (type these yourself, then restart Claude Code):

```text
/plugin marketplace add Technoetic/semantic-crosscheck
/plugin install semantic-crosscheck@semantic-crosscheck
```

Codex:

```text
codex plugin marketplace add Technoetic/semantic-crosscheck --ref v0.1.1
codex plugin add semantic-crosscheck@semantic-crosscheck-local
```

Follow "Plugin setup" and the README quick start. Python 3.11 or later, PostgreSQL 17, Java 11 or later
and Node.js 22 or later remain the minimums for the relevant stages. Cube stays pinned at 1.8.3, and the
adapter dependency lockfile is unchanged. Replace any existing installation's v0.1.0 pin with v0.1.1
through its plugin manager before using the fixes.

## Known limitations

- A pass means the selected checks found no disagreement in the supplied data. Read `not_proven` with
  every verdict; it does not establish all business rules or universal ontology correctness.
- Source-data snapshot or version binding across stages is not added by this patch. Keep the input stable
  throughout a verification run.
- Gold SQL and `sql_violation` predicates remain trusted code. A shared mistake may escape comparison.
- OWL remains open-world and only supported definitions with matching OWL and SQL meanings are compared.
  This is not a general RDF/OWL import or synchronisation service.
- Existing v0.1.0 limits remain: one swept parameter per gold query, the documented query forms, a
  50,000-row Cube response limit, one Cube process per mutant and plain lower-case SQL identifiers.
- PostgreSQL before 17 and client certificate options are unsupported. The roles template is tested with
  a superuser. Linux arm64 and macOS native Cube installations are not exercised end to end by CI.
