# semantic-crosscheck v0.13.0

Release date: 2026-10-29. A minor release adding three opt-in diagnostic contracts. Default pipeline stages and dependency pins are unchanged.

## What it is

semantic-crosscheck generates PostgreSQL hierarchy closures, SQL/SHACL rules, OWL/HermiT reasoning and a Cube semantic layer, then cross-checks them and independently authored gold SQL. This release deepens the evidence around a proposed synthetic repair, an intended aggregate grain and an existing OWL inconsistency. These bounded diagnostics do not establish business truth or automatically change operational data.

## Highlights

- **Authored SHACL repair fixtures.** `shacl-repair --spec FILE` runs real pySHACL over the same supported shapes and independent before/after synthetic RDF, then checks normalized expected report bags, retained shape targets and hard immutable facts. Separate add/remove costs never override preservation. The shipped valid fixture has class/range/property-pair cases; target-deletion evasion fails retention even when the after report is empty. Oversized/uninspectable manifests and source/output aliases prevent unsafe artifact writes. See [repair schema and examples](../shacl-repair.md).
- **Independent grain contracts.** `grain --config FILE --spec FILE` compares independently authored source/group/output/key/filter/null-policy claims with the current undated preaggregate-to-node fragment. One bounded read-only repeatable-read PostgreSQL snapshot checks actual whole-visible-table key uniqueness/nulls and counts selected rows, null-grain exclusions, orphans and fanout. Contract disagreement fails before connection; unsupported, empty, oversized or incomplete evidence never passes. Parsed configuration hashes remain bound through CLI dispatch, module startup and completion. See [grain schema and examples](../grain.md).
- **Bounded OWL inconsistency explanations.** `reason --explain-inconsistency` uses the same HermiT only after `owl:consistency` failed. It removes generated axiom groups under count/time limits and claims subset-minimality only after every retained deletion is verified on the final core. Opaque key ordinals include outside endpoints, preserve parent assertion order and carry a full group manifest verified before reasoning, including numeric-alias cases. The original failure remains. See [explanation scope and examples](../owl-explanations.md).
- **Safe incomplete outcomes.** Large inputs are capped before unbounded axiom sorting/allocation. Worker timeouts terminate owned descendants. Raw assertions, row values, keys, paths and Java stderr are absent from diagnostic reports. Output failures are sanitized and stale temporary links are not followed.

## Compatibility and migration

`shacl-repair` and `grain` are standalone diagnostics outside the required report pipeline. OWL explanation is off unless requested; a consistent ontology does not invoke it. No new solver, Java library or semantic engine is installed. Existing dependency pins and V1–V5 defaults remain unchanged.

Windows-specific containment coverage registers only on Windows; Ubuntu integration retains its strict no-skip requirement. Actual counts are recorded per OS/Python job rather than copying local totals into CI claims.

Rerun `build`, `reason`, `cube`, `verify` and `report` after upgrading because engine fingerprints change. Installing a release neither reruns stages nor validates cached evidence.

## Known limitations

- SHACL repair validation covers a supported nonrecursive class/numeric-range/property-pair profile and explicit preservation obligations, with one pySHACL engine. Normalized report comparison excludes sourceShape, messages and report blank-node labels. It is not full report equivalence, automatic repair or a proof that the chosen repair is correct.
- Grain checks cover selected undated preaggregate-to-node measures and ordinary/partitioned visible tables. Independent declarations are human assumptions. Dates, closure joins, general DAG/multi-hop semantics, actual Cube execution and an independent aggregate-value oracle are outside scope. Rows excluded by the existing NULL-grain policy require explicit permission and remain visible as counts.
- OWL explanations reuse the original HermiT. Minimality concerns removable generated axiom groups with fixed background declarations, not a globally smallest, unique, complete or independently certified explanation. Capped/error searches are not_run and sufficient partial cores are labeled incomplete. The original consistency failure is preserved.
- Bounded results describe the declared fixture/snapshot/profile and do not guarantee future snapshots, completeness, generic grain correctness or shared whole-pipeline data consistency.
- Existing [v0.12.0 limitations](v0.12.0.md#known-limitations) continue to apply.
