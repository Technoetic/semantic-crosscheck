# semantic-crosscheck v0.35.0 — PostgreSQL 17 view/partition/collation disclosures, Z3 row symmetry breaking and DMSG dominator diagnostics

Release date: 2026-11-25.

## What it is

This minor release adds three zero-new-dependency verification upgrades across PostgreSQL 17 catalog hygiene (`doctor`, `grain`, `runtime_provenance`), Z3 finite-domain witness enumeration (`witness.py`), and diagnostic mutation subsumption analysis (`mutation_coverage.py`). Runtime Python requirements (`requirements/*.txt`), default operational pipeline verdicts, default `doctor` output on ordinary permanent populated tables, and the Cube `1.8.3` adapter lockfile are unchanged.

## Highlights

- **PostgreSQL 17 view security options, child-partition hygiene, and collation version drift (`doctor.py`, `grain.py`, `runtime_provenance.py`, `docs/grain.md`, `tests/test_rls_catalog_pg.py`, `tests/test_runtime_provenance.py`):**
  - Parses `security_invoker` and `security_barrier` view options safely in SQL inside `doctor._privileges_sql()` without echoing raw `reloptions` strings, recording `view_security_invoker` / `view_security_barrier` flags and disclosing default view-owner execution (`relkind = 'v'`, `view_security_invoker = false`) in `not_proven`.
  - Extends recursive `pg_inherits` child-partition inspection via a single `LEFT JOIN LATERAL` (zero extra SQL round trips in `doctor`, preserving `statement_budget = 5` in `grain`) to surface foreign child partitions (`child_foreign_partitions`, failing closed in `grain` as `unsupported_relation`), `UNLOGGED` tables and child partitions (`relpersistence = 'u'`, `child_unlogged_partitions`), and child-local `NOT VALID` `CHECK`/`FOREIGN KEY` constraints (`child_unvalidated_constraints`, `coninhcount = 0 AND NOT convalidated`) without leaking relation names in `grain`.
  - Detects PostgreSQL database collation version drift (`pg_database.datcollversion` vs `pg_database_collation_actual_version`) and per-entity column collation drift (`pg_collation.collversion` vs `pg_collation_actual_version`) in `doctor`, and records `collation_version_mismatch` plus a fixed `not_proven` disclosure in `runtime_provenance` so pre-existing glibc/ICU drift is never masked by matching start/end digests.
- **Z3 lexicographic row-order symmetry breaking (`witness.py`, `tests/test_constraint_witness.py`):**
  - Adds `row_symmetry_breaking=True` (default, with `row_symmetry_breaking=False` compatibility option) enforcing non-decreasing lexicographic cell-index order across active rows in each finite-domain table (`counts[table] > row + 1 => row[row] <=_lex row[row + 1]`).
  - Eliminates `k!` SQL bag-isomorphic row permutations (collapsing 24 equivalent 4-row primary-key orderings to 1 canonical fixture and cutting solver checks dramatically) while preserving complete SQL multiset coverage and replay schema v2 compatibility.
- **Diagnostic Dynamic Mutant Subsumption Graph (`mutation_coverage.py`, `docs/mutation-matrix.md`, `tests/test_mutation_matrix.py`):**
  - Computes pure-stdlib DMSG equivalence classes, transitive-reduced direct Hasse subsumption edges, minimal `dominator_classes` (split into `dominator_classes_killed_by_authored` and `dominator_classes_generated_only`), `dominator_representatives`, `subsumed_mutants`, `indistinguishable_mutant_count`, and `redundant_killed_mutant_count` under `subsumption` in `verify/mutation-matrix.json` when `verify.mutant_observation = "all"`.
  - Strictly diagnostic (`diagnostic_only: true`): requires zero extra Cube executions and never alters authoritative V4 verdicts or report status.

## Known limitations

- `doctor`, `grain`, and `runtime_provenance` inspect PostgreSQL catalog state and collation metadata at check time; DDL changes or OS/ICU upgrades after checks run are not retroactively detected until stages are rerun.
- `view_security_invoker = false` discloses default view-owner execution semantics on `relkind = 'v'` relations; `doctor` does not statically parse view definitions or guarantee privilege parity across nested views.
- Z3 row-order symmetry breaking eliminates within-table row permutations under SQL multiset (bag) semantics; it does not break cross-table domain value symmetries or establish general SQL equivalence.
- Dynamic Mutant Subsumption Graph (`subsumption` in `mutation-matrix.json`) reflects observed mismatches on the bounded selected suite and snapshot only; dynamic subsumption on a finite suite is not static/universal mutant subsumption and must not be used to discard tests without independent review.
- Package code and `semantic_crosscheck/__init__.py` version increment to `0.35.0`, which updates `engine_sha256` in stage provenance; rerun operational stages after upgrading.
