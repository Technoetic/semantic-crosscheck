# semantic-crosscheck v0.37.0 — PostgreSQL 17 invalid-index & view-dependency catalog guards, crash-consistent result fsync, DDMIN chunk reduction and Holm-Bonferroni multiplicity diagnostics

Release date: 2026-11-28.

## What it is

This minor release adds four zero-new-dependency verification upgrades across PostgreSQL 17 catalog hygiene (`doctor.py`, `grain.py`), crash-consistent stage verdict persistence (`result.py`), bounded witness reduction (`reduction.py`), and paired release statistical diagnostics (`tools/paired_release.py`). Runtime Python requirements (`requirements/*.txt`), default operational pipeline verdicts, `compat_v0_21_1` default report goldens, `grain` five-statement budgets, and the Cube `1.8.3` adapter lockfile are unchanged.

## Highlights

- **PostgreSQL 17 invalid indexes, transitive view dependencies, and generated columns (`doctor.py`, `grain.py`, `docs/grain.md`, `tests/test_rls_catalog_pg.py`):**
  - Extends `doctor._privileges_sql()` (zero extra SQL round trips per entity) and `grain.evaluate()` (preserving `statement_budget = 5`) to count invalid/unready indexes (`pg_index`: `NOT indisvalid OR NOT indisready`) on both parent relations and recursive `pg_inherits` child partitions (`invalid_indexes`, `child_invalid_indexes`), plus generated columns (`pg_attribute.attgenerated <> ''`, `generated_columns`), surfacing explicit `not_proven` disclosures without leaking relation or column names in `grain`.
  - Adds a zero-extra-round-trip recursive `pg_rewrite` → `pg_depend` CTE (`LEFT JOIN LATERAL` on `relkind = 'v'`) inside `doctor._privileges_sql()` to surface `VOLATILE` functions (`pg_proc.provolatile = 'v'`, `view_volatile_functions`), RLS-enabled underlying tables (`view_dep_rls_tables`), `UNLOGGED` underlying tables (`view_dep_unlogged_tables`), and foreign underlying tables (`view_dep_foreign_tables`) even when the source view sets `security_invoker = true` or references zero base tables.
- **Crash-consistent `Result.write()` durability (`result.py`, `tests/test_result_contract.py`):**
  - Flushes and calls `os.fsync(stream.fileno())` on the temporary `.result-*.part` descriptor before closing and atomically replacing `result.json`, followed by a best-effort POSIX parent-directory `fsync` (`_fsync_dir`, `O_RDONLY | O_DIRECTORY`, suppressing filesystem `OSError`), aligning `semantic-crosscheck` crash consistency with `agentic-vault` and `node-pg-defense`.
- **Bounded DDMIN binary-chunk deletion prelude (`reduction.py`, `tests/test_structured_reduction.py`):**
  - Adds `'chunk_deletion'` to `reduction.OPERATIONS` and executes a deterministic balanced-partition DDMIN binary-chunk deletion prelude before the existing 1-minimal single-row and value-simplification loop on FK-free tables (`len(rows) >= 4`), preserving shared trial budgets, domain validation, `deletion_1_minimal` guarantees, strict `replay_trace` validation (contiguous slices of length >= 2, rejected when foreign keys exist), and `tlp_reduction` step-by-step replay compatibility.
- **Diagnostic Holm-Bonferroni FWER adjustment (`tools/paired_release.py`, `docs/paired-release.md`, `tests/test_paired_release.py`):**
  - Adds pure-stdlib `holm_bonferroni_adjust()` and `build_multiplicity_diagnostics()` emitting a diagnostic-only `multiplicity_diagnostics` (`semantic-crosscheck/holm-bonferroni/v1`) block in `paired_release.py` output across simultaneously evaluated `(exposure, detections/false_positives)` endpoints for both exact and Mid-P McNemar p-values without changing existing `groups`, `pairs`, claim verification, or exit codes.

## Known limitations

- `doctor` view dependency traversal inspects static `SELECT` (`ev_type = '1'`) `pg_rewrite` → `pg_depend` normal dependencies (`deptype = 'n'`) and expands `pg_inherits` over referenced tables at check time; PostgreSQL omits `pg_depend` rows for pinned built-in `pg_catalog` functions (such as `random()` or `clock_timestamp()`), so `view_volatile_functions` covers unpinned user-defined and extension functions only, and dynamic SQL inside PL/pgSQL functions or subsequent DDL changes are not retroactively detected until rerun.
- `Result.write()` parent-directory `fsync` is best-effort on POSIX and skipped on Windows (where file-descriptor `os.fsync()` before `os.replace()` still runs); crash durability also depends on host storage write-cache semantics.
- DDMIN binary-chunk deletion activates only on FK-free tables with at least 4 rows (`len(rows) >= 4`) to preserve reverse foreign-key closure invariants; tables with declared foreign keys continue using single-row and `dependency_group_deletion` passes.
- `multiplicity_diagnostics` applies step-down Holm-Bonferroni FWER control over the evaluated `(exposure, detections/false_positives)` endpoints in one comparison run; it is strictly diagnostic and does not replace pre-registered sample-size planning or sequential anytime-valid e-values.
- Package code and `semantic_crosscheck/__init__.py` version increment to `0.37.0`, which updates `engine_sha256` in stage provenance; rerun operational stages after upgrading.
