# semantic-crosscheck v0.19.0

Release date: 2026-11-05. Preparation record: final-source regression, strict
main/tag integration and publication evidence are recorded after execution;
this source document does not substitute previous release totals.

## What it is

semantic-crosscheck compares PostgreSQL closures, SQL/SHACL rules, OWL/HermiT
reasoning and Cube against independently authored Gold SQL. This release
strengthens the boundaries of evidence it consumes and adds explicit synthetic
diagnostics without giving them operational report authority.

## Highlights

- **Saved-result structures.** Every check must have a nonblank unique ID and
  supported status; malformed list entries are not dropped. Known field types,
  exact version handling and strict JSON decoding precede aggregation.
  Invalid optional-stage files remain errors even when their missing freshness
  fields also make them stale. A valid legacy unversioned file remains
  supported; new writers declare `schema_version: 1`.
- **Live SHACL envelopes.** Validate engine-return types, report root and
  typed conformance, linked result fields/cardinalities and usable generated
  source/focus structure before projection. Errors are sanitized. Warning/info
  API options, legitimate cross-group results and property-pair isolation
  retain their intended semantics; report presence is not equated to an
  allow-warnings API failure.
- **Offline boundary schema.** `boundary-schema --spec FILE` derives NULL and
  exact representable neighbors for one declared integer, numeric(p,s) or date
  scalar comparison. It writes a witness-v1 schema consumable by the existing
  optional Z3 search. It does not connect to a DB, invoke Z3, execute SQL or
  parse arbitrary SELECTs. See [supported grammar and examples](../boundary-schema.md).
- **Opt-in TLP/NoREC reduction.** `tlp --shrink --max-shrink-steps 200` reuses
  structured shrinking. A source-bound v2 replay rechecks the original,
  accepted trace steps and independent final evidence. Default runs and valid
  version1 replay retain their existing behavior. See [TLP scope](../tlp.md).

## Compatibility and migration

Malformed artifacts formerly accepted as a passing subset now produce a
sanitized error. Repair and rerun the affected stage instead of editing evidence
to hide a problem. Version1 is the explicit current saved-result contract;
valid legacy files without its version field remain readable.

The new boundary command and shrink flag are explicit diagnostics. They do not
become required operational stages. No runtime/dependency pin, PostgreSQL
extension, default hook, model call or installed-plugin update is added. Existing
HTTP acceptance/body limits, exact numeric handling and Gold metadata rules
remain applicable. Rerun operational stages after upgrading because the engine
fingerprint changes; installation does not refresh prior evidence.

## Known limitations

- Structural validation does not authenticate maliciously rewritten evidence.
- Boundary generation supports one explicitly declared scalar comparison, not
  a full PostgreSQL parser, arbitrary predicates, complete domain coverage,
  automatic association with caller SQL, or a SQL-equivalence proof.
- TLP reduction preserves signed canonical row-difference support and aggregate
  relation/NULL side; NoREC preserves only count-gap direction. These scopes do
  not identify the same optimizer bug. Live local deletion minimality is bounded
  by the declared signature and budget; replay does not reclaim minimality or
  rerun rejected trials. Errors and instability cannot become accepted witnesses.
- Trusted SQL and synthetic CTEs are not a sandbox. Use reviewed SQL and a
  dedicated test database; no company database is verified by this publication.
- General OWL/RDF support, sampled/exhaustive scopes and non-shared SQL/Cube
  snapshots retain their existing limitations.
- Existing elapsed HTTP acceptance is not forced cancellation of DNS, socket,
  header or framing waits; the source-body cap is not a whole-heap/CPU limit.
- SQLGlot, ProvSQL and ordered-query contracts remain research directions, not
  new dependencies or capabilities in this release. XData is a design reference;
  no third-party source or dataset is copied.
- An unavailable private denylist cannot be certified by an ordinary leak scan.
