# semantic-crosscheck v0.16.0

Release date: 2026-11-02. This minor release extends bounded V4 mutation replay
to every eligible V3 pair chunk and its NULL group, adds per-mutant execution
coverage and offers opt-in enumeration of alternative OWL inconsistency cores.
Dependency pins, default pipeline stages and operational report requirements
stay unchanged.

## What it is

semantic-crosscheck generates PostgreSQL hierarchy closures, SQL/SHACL rules,
OWL/HermiT reasoning and a Cube semantic layer, then cross-checks them against
each other and independently authored gold SQL. This release records which
selected tests actually ran against each mutant and lets an operator request
more than one verified subset-minimal cause of an OWL consistency failure.
These receipts and diagnostics do not certify business truth or add report
authority.

## Highlights

- **Full bounded pair replay.** A passing chunked V3 pair baseline contributes
  every bounded key chunk and a separate NULL-group item to V4, using the same
  in-memory baseline key partition. V4-only verification obtains that baseline
  before expanding the items. Safe item ids append `:chunk[<index>]` or `:null`
  to the V3 check id and identify the exact killing item. Tests at or below the
  pair cap keep their original unfiltered item. Above `verify.pair_key_budget`,
  deterministic sampling and `sample_blind_possible` disclosures remain.
  See [mutation replay coverage](../mutation-coverage.md).
- **Per-mutant execution receipts.** `verify/mutation-coverage.json` and executed
  mutant details record safe item ids, statuses, attempts and explicit unexecuted
  reasons. The artifact includes selected equivalent-on-current-data,
  not-applicable, gated and failed-to-start instances as well as executed
  mutants. Keys and row values are not serialized. `complete` means all selected
  items were attempted; it does not mean they passed or that every possible test
  was selected. The receipt is diagnostic and outside report authority.
- **A separate replay-item budget.** Positive `verify.mutant_max_items` defaults
  to 10000 logical items per mutant. A chunk or NULL group is one item regardless
  of Cube request count, and an error's existing retry stays within that item.
  Exhaustion produces `not_run` with `suite_budget`, never a survival verdict.
  An early confirmed kill remains valid while remaining items retain unexecuted
  reasons. Baseline failures are excluded and disclosed; a survivor of a suite
  left incomplete by baseline failures, closure gates, planning failures or
  `--gold` exclusions is `not_run` (`suite_incomplete`).
- **Alternative OWL cores on request.** After an actual consistency failure,
  `reason --explain-inconsistency --explain-max-explanations 3` can enumerate
  verified alternative subset-minimal generated-group cores. The result cap
  defaults to 1 and accepts 1–32; `--explain-max-search-nodes` defaults to 256 and
  accepts 1–4096. Enumeration shares the existing consistency-call cap and
  deadline with the first-core and uniqueness work. Every retained alternative
  passes fresh deletion checks; the original consistency failure and first-core
  status, minimality and uniqueness fields retain their meaning.
  See [OWL explanation limits](../owl-explanations.md).

## Compatibility and migration

V4's replay expansion and coverage receipts apply to the existing selected
mutation suite. Larger bounded pair baselines can require more Cube requests.
Review `verify.mutant_max_items` when a replay reaches its item limit; raising
`pair_key_budget` alone does not raise the separate item budget. A confirmed
kill is still established only by a failing executed suite item, and excluded
work cannot establish a full pipeline pass. Existing `--only` and `--gold`
scope checks and closure gates remain.

OWL alternative enumeration is opt-in. The default result cap of 1 preserves
the first-core algorithm and consistency-call order, with enumeration reported
as `not_run` (`not_requested`). Requesting more results does not reserve calls
or time for them. Existing defaults remain 128 removable groups, 64 consistency
calls and 10000 milliseconds for the whole explanation. No new runtime dependency
or external implementation is bundled.

Rerun operational stages after upgrading: the engine fingerprint changes with
the package. Installing the release neither reruns stages nor refreshes evidence.

publication. CI conditions alone are not completed execution evidence.

## Known limitations

- Coverage describes selected passing baseline items and selected mutant
  instances. It does not certify general SQL equivalence, future data behavior
  or complete semantic coverage. Equivalent means unobservable on current data.
- Full bounded chunk replay does not create a shared Cube/SQL MVCC snapshot.
  Source changes between requests remain a limitation, and above the key budget
  the existing deterministic sample remains bounded.
- OWL cores concern generated removable groups over fixed declarations, using
  the same HermiT as the baseline. Subset minimality is not minimum cardinality,
  independent reasoner certification or a ranking of source-level causes.
- Enumeration is `complete` only when its frontier is exhausted or first-core
  uniqueness is already established. A result cap, node cap, shared call/time
  limit or worker failure leaves it partial and retains only verified cores.
  Reaching the requested result count does not prove all cores were found.
  Duplicate axiom groups retain the conservative no-enumeration guard.
- Unit exclusions and Windows-host local results do not establish unexecuted
  platform/engine behavior. Public CI evidence reports actual coverage separately.
- Existing [v0.15.0 limitations](v0.15.0.md#known-limitations) continue to apply.
