# semantic-crosscheck v0.3.0

Release date: 2026-10-17. A minor release adding constraint-valid synthetic counterexamples and
optional observed runtime evidence. The configuration format remains version 1.

## What it is

semantic-crosscheck generates PostgreSQL closures, SQL/SHACL rules, OWL/HermiT and Cube models from
one configuration and compares them with each other and hand-written gold SQL. This release adds
optional integrity constraints to synthetic SQL witnesses and binds observed runtime evidence.

## Highlights

- **Declared integrity domain.** `counterexample --constraints FILE` enforces PK, UNIQUE, NOT NULL,
  MATCH SIMPLE foreign keys and allowlisted scalar CHECK predicates on the existing four-table
  synthetic schema. Generated cases and every shrink trial are validated before SQL. An orphaning
  parent deletion is rejected without cascading. NULL-distinct keys, CHECK NULL semantics and typed
  numeric rounding/overflow are checked against PostgreSQL 17.
- **Reproducible constrained witnesses.** Fixtures bind the exact profile bytes, version and mode.
  Changed profiles or modes are rejected before connecting. Constrained text CTEs explicitly use
  `C` collation. A completed shrink proves only minimality among admissible single-row deletions;
  simultaneous deletions might still yield a smaller witness. All-invalid or bounded agreeing
  searches remain `not_run`, never equivalence proofs.
- **Actual runtime observations.** Set `source.runtime_evidence = true` to bind source/Cube PostgreSQL
  versions and semantic settings (including nullable locale/ICU rules), selected Node/Java versions,
  the HermiT JAR/classpath used by owlready2, and selected installed Cube contents. Stage boundaries
  and report check the binding; missing, failed or changed evidence cannot reuse a previous PASS.
- **Bounded probes.** Version output, deadlines and artifact traversal are limited. Probe child-tree
  cleanup is scoped to its own Windows Job/POSIX session. Nonempty Java injection environment
  options are rejected in opt-in mode. Stored evidence has normalized versions, hashes and counts;
  it does not retain DSNs, hosts, local paths or raw probe output.

## Compatibility and migration

Existing version 1 configurations need no new setting. Both features are optional: no integrity
profile means explicitly unconstrained fixtures, and `runtime_evidence` defaults to `false` with no
new runtime probes. Legacy replay fixtures lacking profile binding work only in unconstrained mode.
Existing stage results must be regenerated after an upgrade because the engine fingerprint changes.

Enabling runtime binding requires the **complete installed pipeline**, including for `build`:
PostgreSQL roles, Node.js, Java, HermiT and the selected Cube adapter. It installs or starts nothing.
Full installed-content hashing adds I/O at each boundary and report. Clear nonempty
`JAVA_TOOL_OPTIONS`, `JDK_JAVA_OPTIONS` and `_JAVA_OPTIONS` before enabling it; their values are
never reported. The default disabled mode preserves existing environment behavior.

Requirements remain Python 3.11 or later, PostgreSQL 17 or later, Java 11 or later for HermiT and
Node.js 22 or later for Cube. The Cube 1.8.3 pin and dependency lockfile are unchanged. No new runtime
dependency is added. See the [configuration reference](../../skills/semantic-crosscheck/references/config.md)
and [counterexample reference](../../skills/semantic-crosscheck/references/counterexamples.md).

checksums, not that every business rule is correct.

## Known limitations

The profile language is not a PostgreSQL DDL interpreter or schema discovery tool. Arbitrary CHECK
SQL/functions, column-to-column predicates, deferred constraints, MATCH FULL, NULLS NOT DISTINCT,
application-specific text ordering and nondeterministic collations are not supported.

Trusted SQL can reference real objects explicitly; synthetic CTEs are not a sandbox. Use a dedicated
test database. A witness establishes disagreement between supplied queries, not which business rule
is correct. No global minimum, universal SQL equivalence, shared MVCC snapshot or runtime attestation
is claimed. Observed runtime hashes do not prevent replacement between probes. Data-revision binding
still depends on the source owner's atomic, never-reused revision contract.

The integrity-domain method is informed by [VeriEQL](https://doi.org/10.1145/3649849); no CC BY-NC-SA
VeriEQL code is copied or bundled into this MIT project.
