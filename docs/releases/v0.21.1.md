# semantic-crosscheck v0.21.1

Release date: 2026-11-08.

## What it is

semantic-crosscheck compares PostgreSQL, SHACL, OWL/HermiT and Cube with
independently authored Gold SQL. This release connects explicitly selected
business-definition evidence to report freshness and adds two supported-subset
ways to challenge declarations and assumptions.

The tagged v0.21.0 candidate failed two Windows/macOS test path-spelling
assumptions and was not published as a formal release. This patch compares
canonical paths in those tests, verifies that injected read failures actually
occur, and keeps the production guards unchanged. Exact final-source CI and
asset evidence are required again for this release.

## Highlights

- **Opt-in contract report evidence.** A paired `[semantic_preflight]` contract
  and plan selection requires current successful preflight in the report.
  Missing, changed, mismatched, invalid or non-passing evidence cannot satisfy
  that gate. Reports without the section retain their existing authority.
- **Actual PostgreSQL structural parsing.** Optional `sql-structure --sql FILE
  --expect FILE` compares a bounded SELECT subset against independently authored
  structural expectations. The separately installed pinned pglast 7.22 uses the
  PostgreSQL17 parser. Unsupported constructs and missing/wrong-version parsers
  cannot pass. No SQL is executed, DB queried or operational verdict promoted.
- **Independent bag/provenance fixtures.** Literal synthetic expectations for
  multiplicity, DISTINCT, EXCEPT/EXCEPT ALL and carefully separated NULL behavior
  exercise original reference functions and PostgreSQL companion tests. A pinned
  Lean Dedup/Diff example explains why nonzero annotations are not a general
  proof that a row is returned. This is not a PostgreSQL bug claim.

See [report evidence](../contract-report.md), [SQL structure](../sql-structure.md)
and [fixture scope](../provenance-fixtures.md).

## Compatibility and migration

Core dependencies, Cube pin and existing default stages remain unchanged.
Installing the optional parser is explicit and separate. The implementation
does not install a data-contract engine, Lean or a ProvSQL extension. The ODCS
and Data Contract CLI research informs an internal evidence boundary, not a full
ODCS converter or external quality-test runner. See [licenses](../../THIRD_PARTY.md).

Rerun operational stages after upgrading because the existing engine fingerprint
changes. To opt a configuration into report evidence, select both local sidecars
and run the documented preflight with those exact paths before report. Old or
different-sidecar diagnostic evidence cannot satisfy the new gate. No active
installation, company database or application deployment is changed by publication.


from the installed plugin root. Core/reason installations do not require it.

## Checksums

Assets: committed-source ZIP, `verification.json` and UTF-8/LF `SHA256SUMS`.
Each archive member is compared with its Git blob. Draft and postpublication
downloads are verified independently. Cross-toolchain/timezone ZIP byte
reproducibility is not claimed.

## Known limitations

- Authored definitions, expectations and SQL remain trusted input. Matching
  declarations or structures can share the same mistake; neither establishes
  business truth, data completeness or arbitrary SQL equivalence.
- `reviewed` and local hashes do not authenticate the reviewer or publisher.
- Preflight period declarations do not bind Gold parameters. The separate SQL
  structural diagnostic does not infer business prose, resolve arbitrary names,
  types, functions, casts, CTEs or timezone semantics, or inspect live schemas.
- The parser binding is separately installed pglast (GPL-3.0-or-later); its
  underlying libpg_query/PostgreSQL and other components retain their own licenses.
  No third-party parser source is vendored.
- Formal results retain their hypotheses. The small bag evaluator and literal
  fixtures are original finite examples, not a reproduced Lean build or a proof
  of PostgreSQL/Cube implementations. No production provenance tracing is added.
- Observed input/path guards are not a filesystem lock against hostile concurrent
  ancestor replacement. Existing SQL/OWL/SHACL and synthetic-search limits remain.
- No common Gold/Cube MVCC snapshot is created; source-version checks cannot
  guarantee unrelated sessions observed an identical snapshot.
