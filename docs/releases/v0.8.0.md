# semantic-crosscheck v0.8.0

Release date: 2026-10-23. A minor release adding three opt-in synthetic checks with independent
execution or expected results. Existing version 1 configurations and default stage behavior remain
supported. Auxiliary synthetic evidence does not promote operational V1–V5 coverage.

## What it is

semantic-crosscheck generates PostgreSQL hierarchy closures, SQL and SHACL data rules, OWL/HermiT
reasoning and a Cube semantic layer from one configuration, then compares results with each other
and with hand-written gold SQL. Separate synthetic commands test generated fixtures in dedicated
test environments. Trusted TLP SQL can explicitly reference other relations or functions; its
connection must be restricted to the intended synthetic environment.

## Highlights

- **Actual Cube replay.** `cube-replay` compiles and runs original and named mutant Cube models
  against independently authored gold SQL for all nine supported mutation operators. Only an
  observed result disagreement kills a mutant; missing, failed or malformed execution cannot.
  A dedicated `SXC_CUBE_REPLAY_DSN` and explicit `--allow-scratch-schema` consent are required.
  Private schemas are bound to their creation identity and cleaned without `CASCADE`.
- **SQL three-way partition checks.** `tlp` checks bounded nonrecursive trusted SQL through
  true, false and NULL partitions. `UNION ALL` retains duplicate rows; comparisons include
  `COUNT(*)`, nullable counts and exact numeric sums, including empty and all-NULL inputs.
  Materialized inputs and rechecks detect observable input instability. A dedicated read-only
  synthetic `SXC_TLP_DSN` is required; TLP does not create a persistent scratch schema.
- **Independently expected SHACL reports.** `shacl-corpus` checks eight fixed nonrecursive
  synthetic cases with pySHACL and separately installed Apache Jena: sixteen engine/case checks.
  Canonical result multisets compare focus, path, component, severity and value. Missing,
  partial or malformed reports cannot become valid empty results. Jena 6.2.0 requires Java 21;
  the existing HermiT minimum remains Java 11.
- **Bound replay and clear scope.** Database fixtures bind their exact inputs and configuration
  hashes. New commands reject operational `--config` inputs, retain `not_proven` boundaries and
  report auxiliary results separately. Public summaries contain counts, identifiers and hashes;
  synthetic fixture files are explicitly labelled. SHACL validator processes have time, output
  and owned-descendant cleanup bounds.

## Compatibility and migration

Existing version 1 configurations, legacy fixture replay, default commands and dependency pins
remain supported. The new commands are optional and accept their own synthetic inputs, not the
operational configuration. See the [README](../../README.md) and command references for setup.
Apache Jena is installed separately; CI verifies its pinned archive checksum before execution.
No new external engine is downloaded by the runtime automatically.

Rerun `build`, `reason`, `cube`, `verify` and `report` after upgrading: the engine fingerprint
changes and previous stage results become stale. Installing an upgrade does not certify older
results or rerun stages automatically.

## Install

Claude Code:

```text
/plugin marketplace add Technoetic/semantic-crosscheck
/plugin install semantic-crosscheck@semantic-crosscheck
```

Codex:

```text
codex plugin marketplace add Technoetic/semantic-crosscheck --ref v0.8.0
codex plugin add semantic-crosscheck@semantic-crosscheck-local
```

Install the required Python packages from the actual plugin root and run `doctor`. Only the
optional SHACL corpus command needs the separately configured Jena distribution.

## Known limitations

These are bounded synthetic checks. TLP detects internal consistency defects; it is not a proof
of query equivalence or business correctness. SQL inputs must be trusted: read-only execution
and CTE wrapping are not a hostile-SQL sandbox. Observable stability checks do not establish a
shared MVCC snapshot across independent engines.

Cube replay covers the fixed supported mutation templates, not arbitrary production models.
The SHACL corpus covers fixed nonrecursive cases, not arbitrary shapes, recursive semantics or
every standard feature. Report comparison ignores result-node identifiers, source-shape node
identifiers and human-readable messages, while comparing the declared constraint tuples.

Missing engines, timeouts, malformed output or unsupported inputs cannot pass. No real-data
V1–V5 promotion, universal correctness proof, shared cross-stage snapshot or runtime attestation
is claimed. The existing [v0.7.0 limitations](v0.7.0.md#known-limitations) still apply.
