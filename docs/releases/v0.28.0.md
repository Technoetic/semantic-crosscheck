# semantic-crosscheck v0.28.0 — exact arithmetic and bounded diagnostics

Release date: 2026-11-17.

## What it is

semantic-crosscheck generates PostgreSQL, SHACL, OWL and Cube models from one configuration, then checks agreement with each other and authored evidence. A pass describes only checks that actually ran within their stated scope.

This release fixes V3 additive arithmetic and adds two explicit diagnostics. Existing pipeline defaults, dependency pins and Cube 1.8.3 remain unchanged. Engine fingerprints change; rerun operational stages after upgrading. Publication does not change active plugin installations or company databases.

## Highlights

- **Exact arithmetic:** ambient precision 28 previously rejected the correct total `10^28+1` and accepted the rounded `10^28` for groups `10^28` and `1`. Bounded exact summation no longer depends on ambient precision, rounding or traps. Numeric resources are checked before expansion; nonfinite/oversized values never certify equality.
- **Independent measure oracle:** `measure-oracle --config FILE --spec FILE` exports bounded raw rows from one table, applies independent authored typed predicates and SUM/COUNT, then compares one current Cube measure. No generator imports; joins/grouping/time windows are outside this first scope. Separate raw/Cube sessions are not claimed to share a snapshot. [Contract](../measure-oracle.md).
- **Real plan comparison:** `plan-compare --spec FILE --dsn-env NAME` compares full typed row bags on owned temporary synthetic data in one stable read-only snapshot. EXPLAIN must establish genuinely different sequential/index scan plans. Mismatch is inconsistency, not which answer is right. No arbitrary SQL, generic fuzzer, reducer or minimality claim. [Contract](../plan-compare.md).
- Both diagnostic results contain counts, identifiers, hashes and fixed reasons only, and stay outside default report authority. Inputs changing during inspection/publication and unsafe output aliases invalidate results. No new runtime dependency.

## Known limitations

- Numeric budgets are conservative; extreme inputs are refused rather than rounded into equality.
- The independent measure subset is single-table typed SUM/COUNT. An independent implementation does not prove that the authored specification expresses the correct business rule.
- Raw export/Cube sessions do not share an enforced snapshot; stable-data/revision assumptions remain explicit.
- Plan comparison supports only its declarative synthetic subset and requires observed plan diversity. There is no reducer or minimality claim.
- Diagnostics do not alter default report authority or erase existing not_proven disclosures.
- Existing unresolved Cube adapter dependency advisories are not repaired by this release.

## Research references and reuse

- [Hypothesis](https://github.com/HypothesisWorks/hypothesis): already referenced for counterexamples; generated-input/permutation/boundary-test ideas are extended to numerical regression cases, without a new runtime dependency or copied code.

- [SQLancer pinned source](https://github.com/sqlancer/sqlancer/tree/a513c87781ed879e5aae6bc78f8b6c6056bd7a99): existing differential-testing reference; no source/oracle is copied or installed, and Cloudberry-specific code is not a PostgreSQL drop-in.

CODDTest, SQLSolver and new solver runtimes are not included.
