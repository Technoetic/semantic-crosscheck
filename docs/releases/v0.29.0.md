# semantic-crosscheck v0.29.0 — measure evidence and independent totals

Release date: 2026-11-18.

## What it is

semantic-crosscheck compares a generated PostgreSQL, SHACL, OWL and Cube model against operational checks and separately authored expectations. This release exposes the evidence behind each configured measure and extends the optional raw-row oracle.

## Highlights

- **Evidence per measure.** The first table in the Markdown report and the JSON field `metric_evidence` show what supports each value, date or join facet. Empty comparisons, mutation-only detection and generated-only checks have distinct labels. A comparison can reveal a disagreement. Read its status before interpreting the result. [Report contract](../contract-report.md).
- **Per-item totals over a period.** The single-table spec can group raw rows by one key and select a half-open UTC calendar interval. The Cube query is authored separately. The January example deliberately widens the Cube range to February in a regression test so an unexpected item group becomes visible. [Grouped example](../../examples/measure-oracle/item-window.json).
- **Joined quantity.** When any matching detail row qualifies an order, the raw check counts that order once. In the synthetic case the eligible orders total 26.00. A join that repeats one 15.25 order produces 41.25 and the diagnostic fails. Two different orders can have the same amount. [Runnable join example](../measure-oracle-joins.md).
- No new runtime dependency. Version 1 scalar specifications remain supported. Rerun operational stages after upgrading to refresh engine-bound evidence.

## Install

For a pinned local clone use `git clone --branch v0.29.0 --depth 1 https://github.com/Technoetic/semantic-crosscheck.git`.

```text
codex plugin marketplace add Technoetic/semantic-crosscheck --ref v0.29.0
codex plugin add semantic-crosscheck@semantic-crosscheck-local
```

Claude Code users can add the marketplace with `/plugin marketplace add Technoetic/semantic-crosscheck` and run `/plugin install semantic-crosscheck@semantic-crosscheck`. Follow the [README](../../README.md) for prerequisites.

## Verification evidence

| Evidence | Where to check |
|---|---|
| Unit tests | The release receipt records OS/Python matrix totals and environment-dependent skips from raw logs. |
| Integration tests | The strict integration suite runs PostgreSQL 17, Cube, HermiT and Jena and requires zero skips. It includes passing and deliberately failing grouped-period and fan-out cases. |
| CI run | The receipt links main and tag runs to the published Git commit. |
| Leak scan | Tracked source, history and release files are checked before publication. |
| Independent verification | The receipt binds additional review and archive checks to the release source. |

## Checksums

SHA256SUMS lists the source ZIP and verification.json digests. The archive can be rebuilt from the tagged Git tree using the command in the README.

## Known limitations

- The evidence table describes current verify checks. Standalone expected-row and measure-oracle runs retain their own receipts and exit codes.
- The grouped mode admits one key and a fixed UTC date window. Related-row eligibility supports global SUM and COUNT(column) over one relation. These are bounded checks. Unsupported inputs or exhausted budgets cannot certify a comparison.
- PostgreSQL raw reads and Cube queries run in separate sessions. Use stable source data to interpret differences. The runnable fixtures are synthetic. A business owner still needs to supply representative expected results to verify an actual business rule.
