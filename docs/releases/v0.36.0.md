# semantic-crosscheck v0.36.0 — Fixture tree-membership audit, opt-in assumption allowlists and Python `-O` portability self-audit

Release date: 2026-11-27.

## What it is

This minor release adds three pure standard-library verification upgrades selectively adapted from [`openai/math`](https://github.com/openai/math) (commit `3344da59`, Apache-2.0): exact fixture-directory tree membership auditing in `tools/paired_release.py` and `tools/run_paired_example.py`, opt-in closed-enum report assumption allowlist checking (`sxc.py report --permitted-assumptions`) in `report.py` and `sxc.py`, and production/CI `assert` elimination with a relocated `python -O -B` portability and tamper-rejection self-audit (`tools/portability_check.py`). Runtime Python requirements (`requirements/*.txt`), default operational report outputs (`compat_v0_21_1` byte-identical goldens), default exit codes, and the Cube `1.8.3` adapter lockfile are unchanged.

## Highlights

- **Exact fixture-directory tree membership auditing (`tools/paired_release.py`, `tools/run_paired_example.py`, `docs/paired-release.md`, `tests/test_paired_release.py`):**
  - Extends `audit_fixture_leakage()` with a symlink-safe `os.scandir` membership check against the exact planned `{<case_id>.json}` set, recording `tree_membership_passed`, `extra_files`, `extra_directories`, and `unexpected_entries` using relative names only (zero raw local paths).
  - Fails closed (`exit 1` under `--check-fixture-leakage`) when unlisted fixture files, stray subdirectories, or non-regular entries are present in `--fixtures-dir`, closing the fixture cherry-picking blind spot while keeping `examples/paired-release/cases` (10 cases) green.
  - Enforces exact `cases/` directory membership in `tools/run_paired_example.py` as well.
- **Opt-in structured report assumption allowlist (`report.py`, `sxc.py`, `docs/design.md`, `docs/reference/cli.md`, `docs/reference/check-ids.md`, `commands/xc-report.md`, `tests/test_report_assumptions.py`):**
  - Adds pure-stdlib closed-enum assumption derivation (`ASSUMPTION_CODES`, 17 structured codes derived strictly from existing stage receipts with zero extra database queries or prose scraping).
  - Adds opt-in `sxc.py report --permitted-assumptions <csv|none>`: when omitted, default `report.json`, `report.md`, and `report/result.json` stay byte-identical; when passed, emits `assumption_policy`, renders `## Assumption policy` in `report.md`, and adds check `assumptions:permitted` (`fail`, exit `1`, when any active assumption falls outside the allowlist; unknown codes or malformed lists fail closed with exit `2`).
- **Production `assert` elimination and relocated `python -O -B` portability self-audit (`coverage_matrix.py`, `tools/paired_release.py`, `tools/render_readme_animation.py`, `tools/portability_check.py`, `.github/workflows/tests.yml`, `tests/test_portability_and_asserts.py`):**
  - Replaces the remaining production `assert` statements and all 9 workflow `assert` statements with explicit exception/exit checks, guarded by an AST unit test enforcing zero `ast.Assert` nodes in `skills/semantic-crosscheck/scripts/` and `tools/`.
  - Adds `tools/portability_check.py` (wired into all 8 unit CI cells under `python -O -B`), running relocated-CWD offline verifiers (`knowledge-evolution`, `run_paired_example.py`, `paired_release.py`, `result_contract`, `report --permitted-assumptions`), verifying read-only source SHA-256 immutability, and confirming that 1-byte receipt edits, unlisted fixture files, altered numeric claims, duplicate JSON keys, and disallowed assumptions still fail closed with assertions stripped.

## Known limitations

- `--fixtures-dir` tree membership checks direct entries of the supplied fixture directory against `plan.json`; it cannot detect evaluation cases kept in another folder or never committed.
- `--permitted-assumptions` checks structured trust assumptions recorded by existing stage receipts; permitting an assumption makes the policy explicit rather than establishing that the assumption is safe, and unrecorded runtime changes between stages remain outside report scope.
- `tools/portability_check.py` exercises offline standard-library verifiers under `python -O -B`; live PostgreSQL 17, Cube, HermiT and Apache Jena integration behavior continues to be verified in the strict integration CI job.
- Package code and `semantic_crosscheck/__init__.py` version increment to `0.36.0`, which updates `engine_sha256` in stage provenance; rerun operational stages after upgrading.
