# semantic-crosscheck v0.5.0

Release date: 2026-10-19. A minor release adding an independent closure oracle, operator-directed
synthetic SQL fixtures and opt-in OWL definition witnesses. The configuration format remains version 1.

## What it is

semantic-crosscheck generates PostgreSQL closures, SQL/SHACL rules, OWL/HermiT and Cube models from
one configuration and compares them with each other and hand-written gold SQL. This release adds
independent expected answers for bounded closure checks and synthetic examples. Each result states
its scope; a successful synthetic check does not replace verification on real data.

## Highlights

- **Independent V3 closure oracle.** `v3:closure_oracle:<h>` reads raw edge lines and the stored
  closure in one READ ONLY REPEATABLE READ snapshot, before Cube starts. A separate reverse-topological
  Python calculation uses exact rational arithmetic to compare quantities, logical path counts and
  minimum/maximum depths, without reusing the builder's SQL or temporary tables. Duplicate parent/child
  lines are one logical edge with summed quantity; path counts count paths through logical edges,
  not duplicate source lines. NULL products follow SQL SUM semantics, and null endpoints are omitted.
- **Operator-directed SQL fixtures.** `counterexample --mutation-operator NAME` supports all nine V4
  operator names using deterministic synthetic fixture families. Successful original/mutant query
  disagreement establishes `synthetic_distinguished`. With optional `--gold-sql FILE`, `gold_observes`
  additionally requires original/gold agreement and mutant/gold disagreement. Integrity constraints
  remain enforced during generation and shrinking; replay binds the operator, generator, seed, SQL
  hashes and exact constraint-profile bytes. Query errors are never detections.
- **Opt-in OWL definition witnesses.** `reason --synthetic-witnesses` checks the configured definition
  kinds on small graphs against independently specified memberships and closure pairs. Both HermiT
  and the SQL translation must match the expected results. Nonmember controls test lack of entailment,
  not explicit OWL negation. Configured axioms remain in force, and successful synthetic checks retain
  the real-data empty-class `not_proven` disclosures.

## Compatibility and migration

Existing version 1 configurations need no change. No runtime dependency is added. Python requirements,
the Cube 1.8.3 pin and the dependency lockfile are unchanged.

Rerun the pipeline after upgrading: the engine fingerprint changes, so earlier stage results are
stale (`inputs_changed`). The independent closure oracle runs with V3; the synthetic SQL mode and
OWL witnesses are optional.

Behaviour changes to read before upgrading:

- The closure oracle is bounded, not sampled: 50,000 raw lines, 100,000 stored/expected pairs,
  10,000 nodes and 2,000,000 counted operations, plus numeric-size bounds. Exceeding a resource bound
  is `not_run`; matching only a prefix cannot pass. Unsupported endpoint/quantity types and
  report-mode cycles are also `not_run`. Error-mode cycles, an exceeded configured maximum depth
  and closure differences fail. Query failures are errors. A configuration that previously passed
  without independent closure coverage can therefore require attention before passing in 0.5.0.
- `--mutation-operator` selects its own fixture family and cannot be combined with `--scenario` or
  `--metamorphic-sql`. `--gold-sql` requires this operator-directed mode. Bounded search with no
  successful distinction is `not_run`, never equivalence; a discovered distinction is `fail`/exit 1.
- OWL witnesses use synthetic text keys. They exercise logical translation coverage without claiming
  coverage of every production column type or removing actual-data vacuity.

## Known limitations

The independent closure oracle supports compatible built-in endpoint types with deterministic SQL
equality. Character padding, citext, domains and nondeterministic collation are refused. Report-mode
SCC-edge removal remains unsupported. Empty input lacks nonempty coverage. The database-only oracle
is not replayed as a V4 Cube mutation suite item and shares no snapshot with Cube or other stages.

Operator-directed fixtures compare supplied SQL over a fixed four-table synthetic schema. They do
not establish that the queries correspond to an actual Cube V4 mutation, change a real-data V4 verdict
or prove Cube runtime behaviour. Original/gold disagreement cannot establish gold observation of the
mutant. SQL files are trusted code: qualified external references can still read real objects, so use
a dedicated test database. A row-deletion minimum is not a global minimum or universal equivalence.

OWL controls express lack of entailment, not negative facts. Synthetic text-key checks cover logical
translations only, preserve real-data vacuity disclosures and do not repair impossible positive
examples by removing configured axioms.

Existing limits remain: V3 additivity covers `ontology.class_column`; sampled pair-test detection
bounds depend on independence from the fixed md5 ordering; `class_and_bounds` shapes are SQL-only.
No shared MVCC snapshot across stages, universal SQL equivalence or runtime attestation is claimed.
Data-revision binding still depends on the source owner's atomic, never-reused revision contract.
