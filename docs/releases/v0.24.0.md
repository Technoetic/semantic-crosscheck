# v0.24.0 — observable mutation detectors and authored aggregate examples

Release date: 2026-11-13.

## What it is

This release adds optional bounded observations after the first non-passing mutation-suite item and extends
synthetic test evidence for duplicate joins and aggregates. It does not introduce another verifier engine,
operational measure oracle, runtime dependency or CLI stage.

## Highlights

### Optional mutation matrix

```toml
[verify]
mutant_observation = "all"
# Existing per-mutant logical-item limit; default 10000.
mutant_max_items = 10000
```

Run the usual `verify` command. Default `"first"` retains early stopping. Optional `"all"` continues the selected
baseline-passing replay items within the same item budget and records diagnostic observations in
`verify/mutation-matrix.json`. The authoritative V4 result remains the first non-pass in suite order, including
the existing one-error retry. Later failures never upgrade a first error, first-detector evidence kind, require
mode or report status. The matrix distinguishes mismatch detections from execution, errors and unexecuted
cells and discloses incomplete observations. It contains safe identifiers, categorical states and counts, not
query parameters or source rows. See [the matrix contract](../mutation-matrix.md).

This option costs additional replay work. It observes only selected operators, targets, items and bindings on
the current data; it does not establish general semantic coverage, correctness of authored SQL or a shared
PostgreSQL/Cube snapshot.

### Authored join and aggregate examples

The separate [join/aggregate corpus](../join-aggregate-fixtures.md) contains original literal expected results
for duplicate inner joins, NULL join keys, mixed/all-NULL values, zero/negative integer inputs, multiple groups,
empty grouped results and empty global aggregates. Bounded independent Python arithmetic and actual
PostgreSQL companion tests compare with those literals. Distinguishing wrong variants exercise deduplication,
row-count/non-NULL-count confusion and SUM-to-MAX errors. The existing one-column provenance corpus stays
unchanged.

These are synthetic tests, not a general SQL evaluator, imported proof engine, production dataset validation or
automatically authored operational Gold. StrykerJS, Mutation Testing Elements and SPES are conceptual references
with pinned public evidence in [THIRD_PARTY.md](../../THIRD_PARTY.md); no upstream code is copied or installed.

Engine and configuration fingerprints change. Rerun operational stages after upgrading; publishing this release
does not update active installations or company databases. Existing evidence attribution, accepted gaps,
generated-only disclosures, optional require mode and report authority remain.

skips, artifact hashes and independent verification. Source ZIP, `SHA256SUMS` and that evidence follow the existing
release format. No previous release's test counts or unmeasured performance claims are substituted.

## Known limitations

- The matrix observes selected mutants, suite items and replay bindings only. Errors, timeouts, skipped cells,
  budget exhaustion and data-equivalent mutants are not detections; partially observed detector sets are not
  evidence that other detectors do not exist.
- Later diagnostic detections do not upgrade first-detector evidence or report authority. Additional requests
  cost runtime, whose change has not been benchmarked.
- Gold, Cube and replay reads do not share a PostgreSQL MVCC snapshot. No new immutability mechanism is added.
- The synthetic corpus supports bounded integers, text and NULL with inner equijoins and simple aggregates.
  It is not a production measure evaluator, formal proof engine or a business-definition correctness check.
- Existing generated-only/empty-data evidence limits, accepted gaps and supported-subset engine limits remain.
