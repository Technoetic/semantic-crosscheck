# semantic-crosscheck v0.14.0

Release date: 2026-10-31. A minor release that closes two fail-open paths in the Cube and V4 checks and adds a uniqueness verdict to OWL inconsistency explanations. Dependency pins and default pipeline stages are unchanged; one configuration check is stricter.

## What it is

semantic-crosscheck generates PostgreSQL hierarchy closures, SQL/SHACL rules, OWL/HermiT reasoning and a Cube semantic layer, then cross-checks them and independently authored gold SQL. This release makes a malformed Cube answer an error instead of an empty result, makes the `closure_join_swap` mutation witness exact, and reports whether a bounded OWL explanation is the only one over the generated axiom groups.

## Highlights

- **A malformed Cube answer is never an empty answer.** `CubeClient.load` accepts a `/load` answer only in Cube's load envelope, a JSON object whose `data` is a list of row objects. Any other HTTP 2xx answer without an `error` member, including a body that is not JSON, raises `CubeResponseError`, and the rows of a gold query (V1, V2, their V4 replays and `expect`) must hold every mapped member (`MissingMember`). Read as zero rows or NULLs, such answers used to let V1 and V2 pass vacuously against empty gold rows, let a V3 pair test of at most 2,000 keys pass over no keys whatever the source data held, and count as a V4 kill. V1 and V3 checks now carry `cube=invalid_response` with a next action that points at the adapter; a V2 stratum check counts such bindings by type under `errors`; a V4 suite item is retried once and, when the retry gets such an answer too, the mutant is left unjudged (`suite_error`), never killed.
- **Exact `closure_join_swap` witness.** Cube 1.8.3 aggregates a measure reached through the closure's `many_to_one` join over the distinct primary keys of the measure cube in each group. The witness therefore counts the closure pairs whose two ends join different measure rows instead of comparing values. Witness 0 now means that model and mutant join every closure row to the same measure row, so every query answers the same; observable mutants (equal values on a fork or diamond, NULL against 0, a lone pair seen through the measure's public key) are served and must be killed instead of being skipped as equivalent.
- **Uniqueness of OWL explanations.** A completed subset-minimal explanation from `reason --explain-inconsistency` reports `uniqueness`. One extra same-HermiT check per retained group removes only that group from the full generated set, within the existing call cap and deadline, following the intersection-of-justifications criterion of "Union and Intersection of all Justifications" (arXiv 2109.11216): `unique` when every removal is consistent, `not_unique` when one stays inconsistent, `not_proven` on caps, deadlines, worker errors or repeated generated axioms. See [explanation scope and examples](../owl-explanations.md).

## Compatibility and migration

A verify that passed 0.13.0 with `v4:closure_join_swap:<m>` listed as equivalent can now fail V4 when no gold query observes the change, for example when only the joined measure row changes and the gold queries read only values. Add a gold query that observes it (such as one that maps the measure's key together with the closure dimensions) or treat the survivor as a finding.

A Cube adapter that answers `/load` outside the load envelope, or with rows that lack requested members, now yields `error` checks instead of passes. Check the adapter with `doctor --require cube`.

A repeated value in `ontology.no_children` is now a configuration error (exit 2) for every stage: a repeat generated the same axiom twice and could imitate a second explanation. Remove the duplicate.

Rerun `build`, `reason`, `cube`, `verify` and `report` after upgrading. Installing a release neither reruns stages nor validates cached evidence.

## Known limitations

- The member check covers the rows of gold queries (V1, V2, their V4 replays and `expect`). V3 tests check only the envelope of their own Cube answers and still read a missing member as NULL. A V2 stratum check carries no Cube category, so its next action for binding errors stays general.
- The `measure_filter_drop` and `measure_normalization_drop` witnesses still compare sums with NULL read as 0: on a key whose filtered rows are all NULL, a 0 row that the dropped filter adds changes the sum from NULL to 0, which V1 can see, while the witness stays 0 and the mutant is skipped as equivalent. This is planned for a later release.
- The `closure_join_swap` witness reads its keys from `crosscheck.toml`, not from the served model's measure SQL; a drifted model is caught by the existing V3 totals and model checks rather than by this witness.
- OWL uniqueness reuses the original HermiT and relies on the generated axiom groups only adding axioms (monotonicity). It covers explanations over the generated groups, not a global or independently certified answer. With the default 64 calls and 10 s deadline, real data often ends `not_proven`; raise `--explain-max-checks` and `--explain-timeout-ms`.
- Existing [v0.13.0 limitations](v0.13.0.md#known-limitations) continue to apply.
