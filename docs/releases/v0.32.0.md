# semantic-crosscheck v0.32.0 — PostgreSQL 17 RLS and NULLS NOT DISTINCT catalog guards, anytime-valid e-values, summarizability checks and SQL function boundary seeds

Release date: 2026-11-22.

## What it is

This minor release adds four zero-runtime-dependency diagnostic and catalog-safety improvements: PostgreSQL 17 row-level security (`relrowsecurity`, `relforcerowsecurity`, `rolbypassrls`) and `UNIQUE NULLS NOT DISTINCT` (`pg_index.indnullsnotdistinct`) guards in `doctor` and `grain`, standard-library anytime-valid Safe Testing e-values (`safe_e_value`, `safe_e_log`, `safe_anytime_p`) in `tools/paired_release.py`, OLAP summarizability classification with opt-in `--reject-semi-additive` enforcement in `semantic-preflight` and `grain`, and an empirical SQL built-in function boundary-argument fixture scenario (`function_boundary`) in `counterexample` and `tlp`. Runtime Python requirements (`requirements/*.txt`), default operational pipeline stages and the Cube `1.8.3` adapter lockfile are unchanged.

## Highlights

- **PostgreSQL 17 RLS and `UNIQUE NULLS NOT DISTINCT` catalog guards (`doctor.py`, `grain.py`, `tests/test_rls_catalog_pg.py`):**
  - `doctor` reads `pg_class.relrowsecurity`, `pg_class.relforcerowsecurity`, `pg_roles.rolbypassrls` and (on PostgreSQL 15+) `pg_index.indnullsnotdistinct` inside its existing catalog privilege query with zero extra SQL round trips, recording them on `privileges:select:<entity>` and emitting a `not_proven` visibility-skew disclosure whenever RLS is active on a source relation.
  - `grain` inspects the same catalog flags inside its existing relation-kind check (still within `statement_budget = 5`) and **fails closed** (`not_run`, `reason=row_level_security`) when active RLS filters the check role without `BYPASSRLS`, preventing partial row subsets from passing as complete key/join evidence.
- **Anytime-valid Safe Testing e-values (`tools/paired_release.py`, `docs/paired-release.md`, `tests/test_paired_release.py`):**
  - Adds exact standard-library (`math.lgamma`) Jeffreys Beta(1/2, 1/2) mixture-martingale e-values (`safe_e_value`, `safe_e_log`, `safe_anytime_p`, `min_discordant_for_e_005 = 7`, `underpowered_for_e_005`) alongside fixed-sample McNemar and Newcombe Wilson CI statistics so sequential monitoring across a growing held-out corpus preserves Type-I error control and independent cohorts combine additively in log space.
- **Multidimensional summarizability classification (`business_contracts.py`, `semantic_preflight.py`, `grain.py`, `docs/semantic-preflight.md`):**
  - Classifies each `semantic-preflight` contract into closed summarizability enums (`additive_flow`, `semi_additive_stock`, `distributive_extremum`, `atemporal_additive`, `non_additive_or_custom`) following Mazón, Lechtenbörger & Trujillo (2009), discloses semi-additive `as_of` + `sum`/`count` time-rollup risk in `not_proven` by default, and supports opt-in `--reject-semi-additive` (`reason=semi_additive_stock_conflict`).
  - Maps `grain` violation counts to closed `summarizability_failures` categories (`incompleteness`, `non_strictness`, `null_key`, `null_exclusion`).
- **SQL built-in function boundary-argument scenario (`counterexample.py`, `sxc.py`, `examples/counterexamples/function_boundary-{reference,candidate}.sql`):**
  - Adds the deterministic `function_boundary` scenario to `counterexample` and `tlp`, exercising empty/whitespace/quoted/Unicode text literals, `INT32_MIN`/`INT32_MAX`, signed zero, 18-digit max-precision numerics, extreme calendar dates (`0001-01-01`, `1970-01-01`, `2000-02-29`, `9999-12-31`) and `NULL`s informed by Soft (EuroSys 2025), while leaving all four existing scenarios byte-identical.

## Known limitations

- `doctor` discloses active PostgreSQL row-level security (`relrowsecurity=true`) in `not_proven` and records boolean catalog flags on `privileges:select:<entity>`; it does not evaluate `pg_policy` predicates or inspect Cube's separate DB role credentials.
- `grain` fails closed (`not_run`, `reason=row_level_security`) when RLS filters the check role without `BYPASSRLS`; if the check role holds `BYPASSRLS`, evaluation runs and emits a `not_proven` note because another role (such as Cube) may still see a filtered subset.
- `tools/paired_release.py` e-values remain valid under optional stopping for independent discordant pairs; synthetic fixtures derived from one shared schema are not independent real-world samples.
- `business_contracts.py` summarizability classification inspects authored `(period_kind, context.aggregation)` declarations only and does not prove SQL time-window semantics; `--reject-semi-additive` is standalone opt-in (to preserve v1 compatibility, `report`'s `[semantic_preflight]` sidecar check recomputes default mode and fails closed on `--reject-semi-additive` failure artifacts).
- `counterexample --scenario function_boundary` is a bounded synthetic family covering the fixed 4-table CTE schema; finding no mismatch does not prove SQL equivalence.
- Package code and `semantic_crosscheck/__init__.py` version increment to `0.32.0`, which updates `engine_sha256` in stage provenance; rerun operational stages after upgrading.
