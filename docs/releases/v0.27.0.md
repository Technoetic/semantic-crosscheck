# v0.27.0 — timestamp comparison pitfall, in-range lockfile refresh, end-of-support dates and reference documents

Release date: 2026-11-16.

## What it is

This release documents a way a gold query can disagree with itself, refreshes the Cube adapter lockfile inside its
declared ranges, gives the upstream end of support of every minimum runtime, and moves the README's reference
sections into documents of their own. The engine's behaviour, the default `build` and `report` outputs on
`demo/crosscheck.toml` (apart from the version and the engine fingerprint they record), the Python dependency pins,
the Cube pin (`1.8.3`) and the `v0.21.1+` data-rules compatibility are unchanged.

## Highlights

### A `timestamp` column compared with a `timestamptz` value

- `references/pitfalls.md` adds "Do not compare a `timestamp` column with a `timestamptz` value." PostgreSQL converts
  the column to `timestamptz` in the session `TimeZone`; across a daylight-saving change that conversion does not keep
  the column's order, and an index scan, which assumes it, stops early. On PostgreSQL 17.11 with `TimeZone` set to
  `America/New_York`, 73 rows from 00:00 to 06:00 on 2026-03-08 and `ts < timestamptz '2026-03-08 07:30:00+00'` gave
  36 rows by a sequential scan and 30 by an index scan, and 73 under UTC.
- The harness does not set `TimeZone` for the gold SQL (only the fixture digest of `expect` fixes it to UTC), so the
  pitfall asks for the same type on both sides rather than a fixed zone, which would move windows meant in local time.
- `tests/test_pitfalls_dates_pg.py` reproduces the example on the integration server, checks that the index scan
  misses exactly the six rows from 03:00 to 03:25, and holds the same-type forms to one answer under both plan
  settings in both zones. If a server release stops showing the difference, the test fails and the pitfall text
  changes with it.

### In-range Cube adapter lockfile refresh

- `npm update body-parser qs joi follow-redirects @azure/identity @azure/msal-node fast-xml-parser
  --package-lock-only --ignore-scripts` changed 12 packages and added 2 (`is-in-ssh`, `powershell-utils`, MIT).
  `npm audit --package-lock-only` reports 5 unique advisories instead of 11; the six packages it cleared are held
  outside the advised ranges by `tests/test_cube_unit.py`.
- `@cubejs-backend/*` stay at `1.8.3`, and `package.json`, `native-sha256.json` and the Node.js minimum are
  unchanged. The five remaining advisories (basic-ftp, elliptic, graphql-scalars) stay after updating every package
  within its range; clearing them needs a newer Cube pin or package overrides, which this release does not make.

### Upstream end of support of the minimum runtimes

- The README requirements table gives, for each minimum runtime version, the date or month its upstream support
  ends and the page it was read from (checked 2026-11-16): Python 3.11 about 2027-10 (PEP 664), PostgreSQL 17 2029-11-08
  (PostgreSQL versioning policy), Java 11 at least until 2027-10 (Eclipse Temurin 11, Adoptium support page) and
  Node.js 22 2027-04-30 (Node.js release schedule). Node.js 22 ends first; raising that minimum goes with moving the
  Cube pin. No test depends on today's date.

### README and reference documents

- `docs/reference/cli.md`, `docs/reference/results.md` and `docs/reference/check-ids.md` hold the stages and options,
  the reading of results and the check ids, moved from the README. Each document starts with a title and a
  two-sentence introduction; the moved text is otherwise unchanged apart from heading levels, relative links,
  anchors and section separator lines. The README is 770 lines instead of 1,054, and each explicit anchor of the
  moved or replaced sections, as well as the anchor of the preflight heading, keeps a short stub that links on.
- The tests that read those sections read the reference documents, the document contract tests include them, and
  `tests/test_docs_readme.py` holds the stubs and every link between the README and the reference documents.

## Known limitations

- The five npm advisories above remain in the locked tree; the adapter listens on 127.0.0.1 only.
- The end-of-support dates are the projects' published schedules on the day of the check and can change; the
  repository does not enforce them.
- The daylight-saving test covers one zone and one change (New York, 2026-03-08) on the integration server's
  PostgreSQL 17; other zones and the autumn change are not tested.
- Cube remains pinned at `1.8.3`; upstream Cube pin evaluation is tracked separately.
- Existing verification limits remain: checks between generated layers share configuration mistakes, measures have no
  independent recomputation, and gold, Cube and replay reads do not share one PostgreSQL MVCC snapshot.
