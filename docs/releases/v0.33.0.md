# semantic-crosscheck v0.33.0 — Pre-registered amendment disclosure, paired activation audits, Cube install manifest digests and platform coverage matrix

Release date: 2026-11-23.

## What it is

This minor release adds three Python standard-library-only evaluation-rigor, install-manifest integrity, and platform-coverage disclosure improvements selectively adapted from `ai3inc/foldboost` (`v0.3.0`, commit `ff7ad2208cf52d7692d5d016ba5b788d782256c7`, Apache-2.0; zero new runtime dependencies, zero copied external source, no GPU/biomolecular adapters, no `.pth` interpreter hooks, no Unix-socket servers, and no NumPy dependency). Runtime Python requirements (`requirements/*.txt`), default operational pipeline stages, default `doctor` output, existing `examples/paired-release/` receipts, and the Cube `1.8.3` adapter lockfile are unchanged.

## Highlights

- **Pre-registered core sealing, `claim_limit` and dual-verdict post-hoc amendment disclosure (`tools/paired_release.py`, `docs/paired-release.md`, `tests/test_paired_release.py`):**
  - Adds optional `frozen_core_sha256` (with `--seal-plan` CLI helper), `frozen_utc`, `claim_limit`, and append-only `amendments[]` (`timing: pre_measurement | post_hoc`, `recorded_utc`, `what_changed`, `why`, optional `exclude_case_ids`) to `tools/paired_release.py`.
  - Rejects `amendments` without a verified `frozen_core_sha256`, rejects `measured_utc` preceding `frozen_utc`, and rejects `pre_measurement` amendments dated after `measured_utc` (exit `2`).
  - Always preserves the full pre-registered summary in `groups` and `pairs`, reports `original_groups` alongside `amended_groups` and `post_hoc_altered_summary` inside `amendment_audit` (both with McNemar, Newcombe Wilson CI, and Safe Testing e-values), and supports `--strict-original` (exit `1` when any `post_hoc` amendment alters the pre-registered summary).
- **Treatment-arm `added_check` activation and control-arm zero-leakage silent no-op audit (`tools/paired_release.py`, `tools/run_paired_example.py`, `tests/test_paired_release.py`, `tests/test_paired_example.py`):**
  - Adds optional per-observation `activation` counters (`added_check_calls`, optional `fallback_calls`, strict non-negative integer validation rejecting booleans) and opt-in `--check-activation` (dedicated exit code `70` on `silent_noop`, `control_leakage`, `both_failed`, or `missing_telemetry`).
  - Adds opt-in `--with-activation` to `tools/run_paired_example.py` while keeping default byte-for-byte replay of `examples/paired-release/` unchanged.
- **Cube `installed.json` strict parsing, canonical `manifest_sha256`, structured `near_misses` and `doctor --coverage` matrix (`cube_run.py`, `cube_install.py`, `coverage_matrix.py`, `doctor.py`, `result.py`, `sxc.py`, `tests/test_coverage_and_install_manifest.py`):**
  - Seals newly written Cube `installed.json` manifests with canonical `manifest_sha256` and reads them via a strict JSON parser rejecting duplicate keys, `NaN`/`Infinity`, non-objects, and files exceeding 256 KiB. Tampered digests fail closed (`manifest_digest_mismatch` / `corrupt`), while existing v0.32.0 and earlier unsealed manifests remain backward compatible as `unsealed_legacy`.
  - Adds read-only, zero-path `cube_run.diagnose_install()` structured `near_misses` codes and `coverage_matrix.py` wired into opt-in `sxc.py doctor --coverage` (never changing default `doctor` output, checks, or exit codes) to disclose declared platform support and Cube native pins against actual CI unit/integration verification scope (`ci_integrated`, `ci_unit_only`, `supported`, `not_measured`, `unsupported`).

## Known limitations

- `tools/paired_release.py` timestamps (`frozen_utc`, `recorded_utc`, `measured_utc`) and `activation` call counts are caller-recorded telemetry; they are not cryptographically notarized and passing `--check-activation` does not certify statistical power or SQL correctness.
- `cube_run.py`'s `manifest_sha256` detects accidental corruption and casual edits to `installed.json` rather than acting as a cryptographic signature; `cube-install` and `doctor` still verify `index.node` and adapter files directly against pinned SHA-256 digests.
- `doctor --coverage` reports declared platform support and CI verification boundaries plus local install diagnostics only; it does not execute live PostgreSQL 17, HermiT, or Cube integration suites on non-CI platforms (`win32`, `darwin`, `linux-arm64`).
- Package code and `semantic_crosscheck/__init__.py` version increment to `0.33.0`, which updates `engine_sha256` in stage provenance; rerun operational stages after upgrading.
