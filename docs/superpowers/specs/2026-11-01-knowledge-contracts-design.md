# Knowledge contracts and limited OKF interoperability

The user authorized the first three proposals from the OKF/OpenWiki comparison: bind authored business definitions to expectation contracts, exchange a limited metadata profile, and exercise version transitions. Work from v0.14.0 commit 0fb3855454a8adf28e16d12288e22f8503dabc5f. Implement and integrate locally; public release and live installation are separate work.

## Global constraints

- Python 3.11+; new features use the standard library and existing SXC modules only.
- New source metadata, bound-expect output, and new diagnostics carry controlled check IDs, enums, counts and hashes only. Never include source bodies, SQL, rows, parameter values, DSNs, environment-variable names, absolute paths, arbitrary labels or exception messages there. Existing unbound legacy output remains compatible; bound mode replaces legacy unset-variable/path echoes with controlled coverage notes and sanitized errors.
- Preserve existing operational report gates, whole-input/runtime/revision binding, and expect/operational isolation. New diagnostics never mint operational PASS.
- Opt in explicitly. Existing unbound expectations retain their valid configuration and successful behavior. Do not map verified/human-reviewed/OKF validity to truth, approval or execution success.
- No new network/model calls, external executors, automatic SQL/model import, production DB access, new default hooks or dependency installation at feature runtime.
- Use synthetic tests only. Keep unsupported profiles, unavailable observations, missing evidence and changed evidence distinguishable. Do not downgrade unrelated existing fail/error to a weaker status.
- Leave release version metadata at 0.14.0; document new functionality as unreleased source. Do not push, tag, publish or update installed plugins.

## S1 source binding

The initial supported owner is authored gold.expect. Do not extend grain or operational report input authority in this increment. Preserve the existing spec string and add optional closed spec_source table with required file and sha256, optional object_id and revision. Captured cases must reject it. Labels are caller declarations, not content parsing, object existence or approval evidence.

file is a nonempty project-relative regular-file path, at most 512 characters. Reject absolute/drive/UNC paths, traversal, empty or dot components, control/NUL characters, Windows device components and secret/hidden names. Canonical configuration directory is the root. Reject file/parent symlinks and Windows reparse/junction components and hardlinks. Never read outside the selected root or a source inside output. Do not echo rejected text. sha256 is 64 lowercase hexadecimal characters; labels are strings of at most 128 characters without controls.

Limits apply only to bound cases: 64 cases, 256 KiB per file, 4 MiB total observed content, and 64 KiB public source metadata. Hash opaque bytes; do not interpret source frontmatter or natural language. Existing legacy case counts are not retroactively capped. The supported filesystem threat model is boundary observation on a caller-controlled filesystem: reject outside paths and every observed link/reparse/race, but do not claim protection against a hostile process changing directory ancestors between checks without a kernel-enforced sandbox/handle traversal.

Implement semantic_crosscheck.knowledge_sources with SourceBinding, validate_spec_source(value, ref), preflight(cfg, out), capture(cfg, cases, out=None), and finish(snapshot, result). cases use the existing (gold_index, gold, case_index, case) tuples. SourceSnapshot exposes ok and public(). Public metadata schema is sxc-spec-sources/v1, with count/current/digest/items. Items contain gold_index/case_index/state, expected_sha256/observed_sha256 and binding_sha256 only. A binding digest covers the declared path/labels/hash without disclosing their values. The public representation never includes paths or arbitrary labels.

States are current, changed, missing, blocked, unavailable. current means observed bytes equal the pin, not semantic validity. missing is only FileNotFoundError, other I/O failure is unavailable. Detect file identity/size/mtime drift using bounded reads and before/after metadata; use O_NOFOLLOW when available. Recheck every observed source after the complete capture batch. State observations are not a filesystem sandbox, continuous lock or ABA proof; document the boundary.

CLI must parse and protect expect sources BEFORE ensure_out/discard/error-result writes. Reuse grain's protected preflight pattern and verified configuration bytes. Protected or malformed source preflight may leave a previous result untouched rather than overwrite an input; nonzero exit is mandatory and the stale file is not fresh execution evidence. Direct expect.run repeats protection. Protect configuration/gold/revision/source aliases and source/output ancestors; hardlink/reparse aliases must be rejected before cleanup. Repeat protection on final/error write paths. Harden Result.write to write a unique exclusively created temporary file before os.replace, rather than opening the fixed result.json.part path: an existing hardlink at that fixed path must never be truncated. Preserve destination and serialized result semantics for all existing callers.

If any source is noncurrent before execution, do not connect to any DB. Return nonpassing expect source checks and not_run case checks. For current bindings, execute the existing consent/fixture flow. Reobserve on completion: demote affected passing cases to not_run if sources changed/disappeared/became blocked/unavailable; preserve existing fail/error cases. Source check IDs are expect:spec_source:<gold-id>[<case-index>]. Preserve only the explicit spec_sources namespace when CLI stamps normal inputs; never merge arbitrary module inputs. Unbound mode has no new source reads/checks/namespace.

## S2 producer and preview profile

Add a diagnostic okf stage with mutually exclusive --export DIR or --import-preview DIR. Both require an explicit --config. Export requires repeatable --select GOLD_ID, selects at most 64 existing unique Gold IDs and never defaults to all. --out remains the SXC diagnostic result directory. Preview does not apply changes, execute SQL or consume imported verdicts.

Bundle layout: index.md, manifest.json, contracts/<gold-id>.md. Profile is sxc-verification-contract-metadata/v1, manifest schema sxc-okf-profile/v1, OKF version 0.2. Custom concept type is SXC Verification Contract, not executable Attested Computation. Root index uses root-only okf_version. Generated frontmatter values are JSON literals on one line (valid restricted YAML); parse only this documented subset with json.loads, never eval or general YAML inference.

Export only selected validated IDs, selected member IDs, safe counts, configuration/selected-SQL/engine/source-binding hashes, and static scope/loss declarations. Bypass the generic all-gold/revision inputs_fingerprint dispatcher path for okf; observe only the selected SQL and source files plus the declared configuration and package engine bytes. Do not copy raw TOML/SQL/source content, expectation rows, param values, DSN names or local paths. Source labels/path are represented by binding hashes. Preserve the original configuration and preview input bytes. General OKF fields outside the closed SXC profile are unsupported_profile, not proof of invalid general OKF. Report omission hashes/counts and fixed loss codes rather than arbitrary metadata values. Runtime receipt contents are omitted in v1 and explicitly declared as such.

Manifest keys must be closed and include schema, profile, okf_version, selected, inputs, source_bindings, documents, losses. Documents list exact relative path, ID, bytes and sha256. x_sxc frontmatter carries profile/id and safe digests. Reject extra/missing/tampered files, unsafe/case-colliding paths, unknown/verdict/trust keys, mismatched IDs/hashes and unsupported subset syntax. Strictly bound JSON nesting to 16, manifest to 64 KiB, concept documents to 64 KiB each, bundle total to 4 MiB and directory entries to 256. Check before unbounded reads or traversal.

Require all selected source bindings to be current at export start and completion. Revalidate current trusted local configuration/selected SQL/source bytes before accepting preview. Hash integrity is not authenticity. Validate fresh inputs again before publication/return; an edited source must not yield a current bundle.

Export must not overwrite any existing destination, including an empty directory, or any input/output alias. Use owned staging and no-clobber directory publication (Windows rename, Linux renameat2(RENAME_NOREPLACE), macOS renamex_np(RENAME_EXCL)); if unavailable fail closed. Guard source and output paths before generic CLI cleanup. Clean only the invocation's verified staging, never a caller's destination. No directory ZIP import or remote fetching.

Operational PIPELINE/ALWAYS_REQUIRED stay unchanged. okf is diagnostic-only. Its pass means scoped export/preview completion. Always include not_proven statements for runtime execution, cross-layer correctness, bundle authenticity and import application. Preserve only the stage's explicit okf_profile input namespace when the CLI stamps inputs.

## S3 offline evolution evaluation

Add a standalone diagnostic knowledge-evolution stage. No --config, DB, engine or model execution. Use a bundled fixed reviewed JSON fixture, bounded 64 KiB, schema sxc/knowledge-evolution-fixture/v1. Five fixed IDs T0-T4: normal, change_spec, delete_spec, restore_spec, retire_case. Do not accept arbitrary external code/SQL/path/DSN fields or claim an open-ended benchmark.

Build a temporary synthetic configuration, a pinned source, and in-memory synthetic Result dictionaries with fixed times. Call the actual config loader, inputs_fingerprint, knowledge_sources capture/finish, report.staleness and report.counted_status APIs. Never create operational build/cube/verify/expect result files or call report.run with live probes. Synthetic case evidence remains in memory.

The independent oracle expects source states current/changed/missing/current/retired. T1/T2 demote a retained synthetic passing expectation to not_run through the source guard. T3 restores exact bytes: binding may legitimately become current, but must not promote the retained not_run expectation, create receipts/change timestamps or claim new engine execution. T4 removes the authored case from the temporary configuration: actual configuration hash staleness rejects old operational synthetic receipts, and actual expect.run on no cases yields not_run before DB. There is no new product tombstone/epoch policy.

Expose run(cfg=None,args,out) -> Result and an evaluate helper suitable for tests; include public fixed checkpoint IDs, source-state enums and actual check counts only. Mode is synthetic_contract_replay; engines_executed/database_queries/model_calls are 0; semantic_coverage_measured is false. Keep original whole-input hash guards. Retain every expected checkpoint/contract in the denominator even when an observation fails. Static scope notes distinguish harness behavior from business truth. Preserve only the explicit knowledge_evolution input namespace with fixture/engine hashes in CLI stamping.
