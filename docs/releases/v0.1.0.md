# semantic-crosscheck v0.1.0

Released 2026-10-14. First public release.

## What it is

semantic-crosscheck is a verification harness for an ontology plus semantic layer built on PostgreSQL 17.
From one configuration file, `crosscheck.toml`, it generates a hierarchy closure, SQL and SHACL data rules,
an OWL ontology reasoned with HermiT and a Cube data model, then checks that these layers agree with each
other and with hand-written gold SQL. Every check has an id, counts and a `crosscheck.toml` entry to fix,
and every result says what the run could not prove. It runs from the command line (`sxc.py`), as a Claude
Code plugin and as a Codex plugin. Source data is only read, and results carry counts and ids, never row
values.

## Highlights

- **Eight stages** (`doctor`, `demo`, `build`, `reason`, `cube`, `verify`, `report`, `cube-install`) with
  fail-closed results: `not_run` is never a pass, a run narrowed with `--only`, `--gold` or `--hierarchy`
  never passes, and `report` passes only when every required stage ran, is current and passed.
- **Closure in PostgreSQL 17**: exact path counts and path-product quantities computed level by level,
  cycle examples with `CYCLE`, applied with `MERGE ... RETURNING merge_action()` and proven equal to the
  recomputation.
- **SHACL against SQL** row key by row key, and **OWL against SQL** (consistency, transitive closure,
  defined classes) with HermiT.
- **Cube against gold SQL**: strict comparison in the form of each column's Cube member type, a
  deterministic strata sweep, query shapes derived from the model (totals, additivity, measure pairs) and
  mutation tests whose witness queries separate equivalent mutants from blind spots of the gold suite.
- **Least privilege by default**: a loader role used only by the demo and a check role that `doctor`
  proves cannot write, own or create in the source tables; read-only, time-limited Cube sessions on
  127.0.0.1; credentials only in environment variables; TLS following the DSN's `sslmode`.
- **Pinned supply chain**: the Cube adapter installed with `npm ci --ignore-scripts` from a committed
  lockfile and a size- and SHA-256-pinned native module; Python dependencies pinned; CI actions pinned by
  commit SHA.
- **A known-answer demo** with a clean and a dirty variant, whose reference numbers come from an
  independent Python implementation and name the check that shows each planted defect.

## Install

Claude Code (type these yourself, then restart Claude Code):

```text
/plugin marketplace add Technoetic/semantic-crosscheck
/plugin install semantic-crosscheck@semantic-crosscheck
```

Codex:

```text
codex plugin marketplace add Technoetic/semantic-crosscheck --ref v0.1.0
codex plugin add semantic-crosscheck@semantic-crosscheck-local
```

Then follow "Plugin setup" and the quick start in the README: Python 3.11 or later with the pinned
requirements, PostgreSQL 17 with the roles from `docs/setup-roles.sql`, Java 11 or later for `reason`,
Node.js 22 or later for the Cube stages (on Linux with glibc 2.34 or later for x64, 2.30 for arm64).

## Verification evidence

The evidence is published with the release rather than in the source tree, because a commit cannot name its
own CI run. The release page lists it, and the `verification.json` asset records it with the commit and the
SHA-256 of the archive (`SHA256SUMS` covers both files):

| Evidence | Recorded in |
|---|---|
| Unit tests, `python -m unittest discover -s tests` | `verification.json`: `tests.unit` |
| Integration tests with PostgreSQL 17, Java and Node.js 22 (`SXC_TEST_ADMIN_DSN` set) | `verification.json`: `tests.integration` |
| CI run of the release commit (unit matrix, integration, demo end to end, hygiene) | release page and `verification.json`: `ci` |
| Clean and dirty demo end to end | `verification.json`: `pipeline` |
| Leak scan of the working tree and the full history, with the private deny-list | `verification.json`: `leak_scan` |
| Independent verification (a second session reran the commands above from a fresh clone) | `verification.json`: `independent_verification` |

## Checksums

The release has a `SHA256SUMS` asset with the SHA-256 of every archive attached to the release. Check a
download before you use it:

```text
sha256sum -c SHA256SUMS --ignore-missing          # Linux
shasum -a 256 -c SHA256SUMS --ignore-missing      # macOS
Get-FileHash semantic-crosscheck-0.1.0.zip -Algorithm SHA256   # Windows PowerShell: compare with SHA256SUMS
```

The archives are made from the tag with LF line endings (the repository's `.gitattributes`), for example
`git -c core.autocrlf=false archive --format=zip --prefix=semantic-crosscheck-0.1.0/ -o
semantic-crosscheck-0.1.0.zip v0.1.0`, so the same tag always gives the same files.

## Known limitations

- A pass means only that these checks found no disagreement on this data. Read the `not_proven` lines with
  every verdict: empty strata, equivalent mutants, shapes compared only in SQL (`sql_violation`, `class`
  combined with bounds, `shared_path`), vacuous defined classes, pair tests over more than 2,000 keys
  (compared on a deterministic sample) and components that are not installed.
- The gold SQL and `sql_violation` predicates are trusted code; a mistake they share with the configuration
  goes unnoticed.
- OWL is open-world: only definitions whose OWL and SQL meanings coincide are compared.
- One swept parameter per gold query; `timeDimensions` take a `dateRange`, not a `granularity`;
  `closure_join` needs exactly one hierarchy; identifiers must be plain lower-case SQL names.
- Cube 1.8.3 is pinned; a Cube query returns at most 50,000 rows; V4 starts one Cube process per mutant.
- PostgreSQL before 17 is not supported; client certificates (`sslcert`, `sslkey`) are not supported, and
  pg8000 does not read `~/.pgpass`.
- The roles template is tested as a superuser only.
- macOS and Linux arm64 Cube installs are pinned and hash-checked but were not run end to end for this
  release.
