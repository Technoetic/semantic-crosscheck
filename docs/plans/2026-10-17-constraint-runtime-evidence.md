Constraints profile shape: {"version":1,"tables":{"part":{"primary_key":["part_id"],"unique":[],"not_null":[]}, ...},"foreign_keys":[{"table":"stock","columns":["part_id"],"references":{"table":"part","columns":["part_id"]}}],"checks":[{"table":"bom_line","column":"qty_per","op":"gt","value":"0"}]}.

Only the fixed SCHEMA tables/columns are permitted. Primary keys imply non-null; UNIQUE uses PostgreSQL default NULL-distinct behavior; FK uses MATCH SIMPLE null behavior and must reference a declared PK/UNIQUE key; CHECK NULL passes unless not_null declared. CHECK operators eq/ne/lt/le/gt/ge/in with finite type-compatible scalar/list literals; no eval or arbitrary SQL. Typed canonicalization follows declared SQL column types. Constraint truth must be conservative and verified against real PostgreSQL boundary cases. Supported constraint domain is explicit, not all PostgreSQL DDL features. Reject shrinking deletions that violate domain instead of cascading, preserving meaningful domain-constrained row-deletion minimality. Existing legacy fixtures without profile stay readable only in legacy mode; mismatched profile/mode cannot replay.

Two implementation tasks are independent: counterexample/CLI/new constraint module/tests vs runtime/config/provenance/result/report/tests. Host owns docs/acceptance and isolated test environment. Root coordinates any shared file changes. Existing revision evidence does not prove shared MVCC; runtime evidence does not fix that limitation.

Final profile semantics force COLLATE C on constrained text CTEs and reject ordered text CHECKs. Runtime probes reject nonempty JAVA_TOOL_OPTIONS/JDK_JAVA_OPTIONS/_JAVA_OPTIONS in opt-in mode. Evidence observes stage boundaries and is not runtime attestation. No noncommercial VeriEQL code is copied, and no runtime dependencies are added. No remote push or release is part of this increment.
